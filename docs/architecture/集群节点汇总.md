# 集群节点汇总

`GET /api/v1/domain/cluster-inventory` 继续按 `limit`、`after` 分页返回 `items`，同时在 `summary` 中返回与当前页无关的全量汇总。范围是当前账号在请求时具有有效 `read` 授权的节点；POD 列表仅包含同时有权读取的 POD 及其有权读取的节点。无关系、无权查看父对象或存在冲突关系的节点计入 `topology_unknown_nodes`。已登记但无可见成员的 POD 不列出。

节点明细只有在归属明确且节点与父组均可读时才返回 `pod_ref` 和 `pod_name`。下钻用 `pod_ref` 精确筛选明细，分页及筛选期间的全量汇总保持同一口径。无权查看和不存在的 POD 返回相同的 404。

POD 归属只能来自台账中的明确关系：父资产的 `kind` 须为 `pod`，并有当前有效的 `physical_parent` 或 `physical_component` 关系直接指向节点。名称、基准方案和发现范围不用于推断成员。受信任的数据目录操作者可以在服务停止后用 `clusbot import-domain-assets --account <现有登录名> --file <清单> --data-dir <实例目录>` 导入，例如：

```yaml
assets:
  - object_ref: group-a
    kind: pod
    identity: 机组 A
    allow_read: true
  - object_ref: node-a
    kind: node
    identity: 序列号-A
    pod_ref: group-a
    allow_read: true
```

清单中节点和 POD 的顺序不限，也可引用已登记的 POD。`pod_ref` 可省略，省略不会删除既有关系；重复导入相同归属不会产生重复关系。引用不存在或类型错误的对象、与已有物理父关系冲突时整份导入回滚。需要变更已有归属时须先处理原关系，导入不会静默迁移节点。导入仅写显式指定的活跃账号已经初始化、且归属匹配的私有库；权限授予该账号。不会写实例库的资产或授权，不会自动开库、改归属或迁移未归属数据。

健康统计读取截至汇总时每个节点最近一条 `asset_transitions.health`（`healthy`、`degraded`、`unhealthy`、`unknown`）；这与资产生命周期状态分开，也不代表实时监控。没有健康记录时为未知；只要有未知节点或没有节点，健康率为 `null`。异常列表按不健康、降级、未知排序，最多返回 20 条；同时返回完整待关注数量。页面标明记录可能不是实时数据。
