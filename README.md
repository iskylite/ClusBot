# ClusBot

ClusBot 是以受托工作为中心的本机 Personal Agent。它使用工作区材料、个人记忆和已授权的 MCP 工具，把一件事从受理、执行推进到成果交付和人工验收。后端为 Go，前端为 React + TypeScript，数据保存在本地 SQLite 和工作区。

## 开发与本机运行

构建需要 Go 1.26 或更新版本、Node.js 22.12 或更新版本、npm 和 Make。从仓库根目录运行以下命令。

```sh
make build
./bin/clusbot serve --demo --data-dir ./data/local
```

打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)，使用启动日志中 `token_file` 指向的口令文件登录。首次启动自动创建 SQLite 数据库、口令文件和工作区。工作区默认位于数据目录下的 `workspace/`，其中 `materials/` 放输入材料，`outputs/` 保存确认写入的成果。省略 `--data-dir` 时使用 `./data`；可用 `--workspace-root` 和 `--listen` 指定工作区和本机监听地址。

`--demo` 使用明确标记的本地演示回复，可用于走通事项受理、成果、写入确认和验收。使用真实模型时，按下文配置后去掉 `--demo`。

当前开发版本从一份完整 schema 创建新库。版本 43 至 46 的数据库会自动升级，其他不受支持的版本会被拒绝。日常开发可重复使用本版本已经初始化的目录。

修改前端时可用 Vite 热更新。先在一个终端构建初始静态资源并启动 Go 后端：

```sh
npm --prefix web ci
npm --prefix web run build
go run ./cmd/clusbot serve --demo --data-dir ./data/dev --listen 127.0.0.1:8081
```

在另一个终端启动前端：

```sh
npm --prefix web run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)，使用后端启动日志中的口令。Vite 会将 API 请求转发到 8081。修改 Go 代码后重启后端。初始静态资源用于 Go 的内嵌资源构建，修改前端时由 Vite 热更新。

安装前端依赖后，运行 `make test` 执行前端类型检查、生产构建和全部 Go 测试。

## 打包与运行

```sh
make release
```

产物是 `dist/clusbot-<GOOS>-<GOARCH>.tar.gz`，包含内嵌前端的 `bin/clusbot`、`configs/example.yaml` 和 `README.md`。例如，在 macOS Apple Silicon 上打包后可用以下命令启动：

```sh
mkdir -p /tmp/clusbot-release
tar -xzf dist/clusbot-darwin-arm64.tar.gz -C /tmp/clusbot-release
cd /tmp/clusbot-release
./bin/clusbot serve --demo
```

运行压缩包里的二进制无需安装 Go 或 Node.js。按启动日志给出的地址和口令文件登录。MCP stdio 服务的额外运行依赖由连接提供方说明。

### macOS 桌面版

在装有 Xcode 命令行工具的 Mac 上运行 `make dmg`，产物为 `dist/ClusBot-arm64.dmg`，适用于 macOS 14 或更新版本的 Apple Silicon Mac。

挂载镜像，将 `ClusBot.app` 拖到「应用程序」，然后双击启动。应用会启动本机服务并自动建立会话，在自己的窗口中显示界面。退出应用会停止随它启动的服务。数据保存在 `~/Library/Application Support/ClusBot`。

桌面界面默认随窗口缩放，长内容在各栏内滚动。「显示」菜单可放大、缩小或恢复适应窗口。未发送的对话和事项草稿、未保存的记忆编辑可在退出应用后继续。下载成果或工具回执时，系统会询问保存位置。

本机构建使用临时签名，供本机使用。

## 模型与运行配置

复制 [configs/example.yaml](configs/example.yaml) 为本地配置，填写实际支持文本流与函数调用的模型端点：

```yaml
server:
  listen: 127.0.0.1:8080
data_dir: ../data/local
model:
  provider: chat_completions
  base_url: https://api.example.com/v1
  model_id: your-model-id
  api_key_ref: env:CLUSBOT_MODEL_API_KEY
runtime:
  max_active_runs: 2
  max_run_seconds: 600
  model_timeout_seconds: 120
  max_output_tokens: 4096
  max_model_request_bytes: 524288
```

```sh
./bin/clusbot serve --config ./configs/local.yaml
```

相对路径以配置文件所在目录解析。在「设置」选择 Chat Completions 或 Responses，填写 API 根地址、模型 ID 和 API Key。应用将密钥明文保存在本地 SQLite，数据库备份也会包含密钥。保存后的密钥优先使用，未保存或移除后读取配置的环境变量（默认 `CLUSBOT_MODEL_API_KEY`）。测试连接会使用当前输入，在 30 秒内检查流式文本、一次应用内测试函数调用及工具结果回传。测试仅使用临时测试码。清空模型 ID 并保存可停用外部模型。

新配置默认使用 Chat Completions，已有配置升级后保留 Responses。服务地址填写 API 根地址（如 `https://api.openai.com/v1`），应用会按协议追加 `/chat/completions` 或 `/responses`。

设置页的「获取模型」使用当前服务地址和密钥请求 API 根地址下的 `/models`。模型 ID 始终可手填。服务返回上下文长度、图片输入类型或推理参数时，页面会填入已知属性。缺失项保留为未知，也可手动补齐或覆盖并保存。模型属性用于记录规格，当前任务仍按原有的输入格式和请求预算执行。

模型设置首次从 YAML 导入 SQLite，之后页面保存的值会保留。设置 `CLUSBOT_MODEL_BASE_URL` 或 `CLUSBOT_MODEL_ID` 时，对应字段在页面只读。`--demo` 模式下日常工作仍使用演示回复，设置页可单独测试外部端点。

执行时间与输出预算按 Run 累计，排队和等待用户确认不计入执行时间。模型未报告的 Token 显示未知；异常退出后的时长标为已保存记录的下限。继续执行沿用原预算，预算耗尽后可用「重新执行」开启同一事项的新 Run。

`max_model_request_bytes` 限制每次序列化后的模型请求，默认 512 KiB，可设为 4 KiB 至 2 MiB。超限时优先省略较早的完整对话轮次，保留当前要求、材料及成对的工具调用与回执；必需内容仍超限时保留事项并说明原因。

## 完成一件事

1. **交代工作。** 从总览输入目标，可选择工作范围、材料、读取工具和验收条件。明确委托建立一个 Task，普通问答保留在「对话」。在已有对话中明确委托，也可继续成为一件工作。
2. **查看执行。** 助手按需查找、搜索和读取 `materials/` 内的文本与 Markdown，或选择已授权的 MCP 读取工具；每轮最多调用 8 次工具。「执行记录」保存各轮输入、读取回执、用量和成果。缺少必要信息时，原事项进入「需要你决定」，回答后继续同一事项。
3. **检查成果。** 结果可预览、下载。补充要求会在同一个 Task 下创建新 Run，保留之前的成果版本；空闲时可编辑标题、目标、范围、验收条件和交付文件名。
4. **保存文件。** 在成果旁选择「保存到工作区」，检查目标后批准。新建文件和覆盖文件分别显示；覆盖前展示差异并绑定当前版本。目标发生变化时需重新检查和批准。
5. **验收。** 确认成果满足要求后点击「确认完成」。验收记录保存当时的条件和成果版本；指定了 `outputs/` 交付文件名时，还必须先批准写入，验收会重新读取文件并核对 SHA-256。文件缺失或被改写时不能直接完成。

工作可以暂停、停止和继续。页面关闭不会停止已受理的执行；进程退出或机器休眠会中断实际处理。恢复时保留已保存的消息、成果、回执和用量，结果不明的读取或文件写入先核对。运行结束时先保存结果回执，再提交成果、状态和用量。回执已持久化而收尾事务失败时，同进程重试或重启均只恢复结果保存，不重新调用模型或工具；恢复仍遵守暂停、停止和执行代际。回执未能写入时，重启后保留中断状态，不认定完成。

工作总览按待决定、处理中和最近完成排列事项；「事项历史」可查已停止工作，按状态、范围和关键词筛选。成果列表可按工作范围查找，历史成果保留原验收标记。普通对话支持历史分页、重命名、归档、恢复和删除，也可以停止排队或生成中的回复。

主会话根据当前消息和近期事项判断新委托、补充要求、进度查询、暂停、停止或澄清。发给正在运行事项的纯文本补充会持久排队，等本轮提交成果或待补充问题后进入下一轮。执行详情 API 的 `contexts` 可追溯各次模型请求使用的消息、材料、记忆、Skill 版本和请求摘要。

主会话可把一条消息中的多个独立要求分别交给对应事项，或分别创建新事项。回复逐项显示已受理、已排队或需要澄清的内容，可在原对话中继续回答指定问题。互斥控制、任务依赖冲突、目标状态变化及归属不明的附件只暂停相关意图。发送回执及执行详情 API 的 `router_intents` 保留原话、稳定编号、处理结果和相关事项。

在「对话」可以发送「把周报的目标改成汇总本月项目风险，并把会议纪要设为高优先级」。修改目标会保存新的任务修订，已排队的旧运行会中断，随后可选择「按新要求执行」。若任务正在执行或已有子任务计划，Router 会单独询问如何处理。优先级分为高、普通、低。同档位按入队顺序执行，调度仍遵守任务依赖。正在执行的任务继续使用已绑定的目标和验收条件。

「先做周报，再做会议纪要」会直接调整这两个排队事项本轮的先后顺序。后做事项在先做事项被领取后可按原依赖继续调度。两项仍在排队时，可以明确反转顺序。任务依赖冲突、循环顺序或对象不明时，只澄清相关要求。

周期目标通过 `GET /api/v1/goals` 查看。`POST /api/v1/goals` 接收 `client_request_id`、`target`、`scope_label`、`acceptance_criteria`、`next_at`、`expires_at`、`interval_ms` 和 `remaining`。时间使用 Unix 毫秒，最短间隔一小时，最多 30 次。同一目标的活跃运行不重叠，离线错过多个周期时合并为一次。周期事项不自动选择 MCP 工具。`POST /api/v1/goals/{id}/stop` 接收当前 `revision`，停止目标及所属活跃事项。

父子任务计划通过 `POST /api/v1/workflows` 提交。请求包含父任务的 `client_request_id`、`goal`、`acceptance_criteria`、`scope_label` 和 `steps`。每个子任务填写 `key`、`goal` 和 `acceptance_criteria`，可用 `depends_on` 引用同组子任务的编号。`optional: true` 表示显式停止该子任务后，父任务可汇总其余验收结果。若其他子任务声明依赖它，仍需验收成果。计划最多八个子任务，依赖必须无环。`GET /api/v1/tasks/{id}/workflow` 可按父任务查看子任务和依赖。计划中的任务不自动选择 MCP 工具，依赖正文超出请求预算时保留中断状态。

普通事项首次执行时，支持工具调用的模型可为确实需要独立验收的工作提出 2 至 4 个子任务。运行时复核任务修订、负责人、控制状态和依赖关系，将本轮剩余的输出和执行时间均分给子任务的首轮及父任务的汇总轮。子任务沿用父任务已选的材料，沿用正常的成果验收流程。周期事项、已有计划的事项、子任务和明确指定读取工具的事项沿用各自的执行流程。计划回执可跨重启恢复。

## 材料与个人记忆

将 UTF-8 `.md`、`.txt` 文件放入工作区 `materials/`，在输入框选择材料。每次最多 4 份，每份最多 32 KiB，使用选取时保存的快照。也可上传最多 10 MiB 的文件；长文件按 UTF-8 字符边界分段，选择进入本次输入的片段。

补充要求默认沿用先前选定的材料。输入过大时，可勾选「替换此前材料」并选较短的摘要或留空；新选择成为后续执行的材料起点，原附件仍可从相关交流追溯。

在「个人记忆」新增、搜索、置顶、编辑或删除偏好与长期事项；也可发送「请记住：以后写纪要先写结论」，或用消息旁的书签保留来源。偏好补充当前请求没有指定的默认选择，个人事项按关键词匹配。使用外部模型时，匹配内容随请求发送。编辑和删除影响后续请求；来源会话删除后，独立保存的记忆仍保留并显示来源状态。

同一非空范围内、目标一致且已经验收的旧成果可作为交付形式示例，随模型请求携带简短摘录和来源摘要。归档的来源不再用于新请求。

验收成果后，「个人记忆 → 经验候选」会列出候选及其来源、验收条件和最多五个文档标题。通过工作消息旁的书签打开原消息，再选择「标记原消息为纠正」，可保留明确的用户纠正。在候选页可查看来源并选择保留或驳回。候选保留后可供后续评测使用，生产请求仍沿用当前经验路由。

旧成果可用 `POST /api/v1/experience-candidates/from-acceptance` 按 `task_id` 和 `artifact_id` 补录。纠正入口 `POST /api/v1/experience-candidates/from-correction` 接收 `message_id`，还可指定同一任务的较早成果 `counter_artifact_id` 作为反例。审阅接口按 `revision` 和 `decision` 更新候选。来源归档、范围变化或验收版本失效时，候选正文将隐藏。


通过 `GET /api/v1/skills` 查看工作方法的版本，`POST /api/v1/skills` 用 `scope_label`、`instructions` 和 `revision` 创建草稿，新范围使用修订 0。确认后将草稿的 `version`、当前 `revision` 和 `sha256` 提交到 `POST /api/v1/skills/{id}/activate`。同一接口可恢复已批准的旧版本，`POST /api/v1/skills/{id}/disable` 按当前修订停用。发布新版后，已绑定的运行继续使用原版；停用 Skill 或回滚到低于已绑定版本时，拦截后续模型请求。Skill 随任务范围使用，工具权限仍由工具授权决定。

委托、补充要求、普通对话和记忆编辑分别保留草稿。同一标签页切换和刷新可恢复；失败或版本冲突保留输入，成功保存或明确取消才清除。主动退出清除本标签页的草稿。发送回执未确认时先核对原请求，只有明确选择「重新判断并发送」才重新分类。

经验策略评测用同一份 JSON 用例，分别执行无经验、现行策略和候选策略。现行组复用生产中的同范围、同目标成果选择。候选组最多选三条有效且已保留的同范围、同目标候选，优先使用完整的用户纠正。评测以只读方式固定来源，直接调用同一个模型，每组使用同一输出上限和请求超时。用例里的 `source_task_id` 与顶层 `holdout_task_ids` 所列任务会从三组的经验来源中排除。

```json
{
  "cases": [
    {
      "id": "weekly-summary",
      "goal": "整理本周项目周报",
      "scope_label": "项目 A",
      "prompt": "写本周摘要。本周完成了回归测试。",
      "required_text": ["回归测试"],
      "forbidden_reuse": ["OLD-88"]
    }
  ]
}
```

把用例保存为 `eval-suite.json`，使用当前版本的数据库备份。模型密钥从 `CLUSBOT_MODEL_API_KEY` 读取，可用 `--key-env` 指定其他环境变量。

```sh
./bin/clusbot evaluate-experience \
  --database ./clusbot-backup/clusbot.db \
  --suite ./eval-suite.json \
  --base-url "$CLUSBOT_MODEL_BASE_URL" --model "$CLUSBOT_MODEL_ID" \
  --max-output-tokens 1024 --timeout 30s > experience-report.json
```

报告逐用例记录输出、来源及版本、失败断言、Token 和耗时，并按策略汇总。成功率的分母是全部用例，模型失败也计入。错误复用率的分母是已完成且设置了禁用标记的用例。建议选取旧经验独有、当前材料里没有的标记。命中标记表示违反该用例的字面断言。模型未报告的用量显示为 `null`，总量按已知用量汇总并附覆盖数。评测只执行固定文本生成，工具环境为禁用状态。

在「个人记忆 → 经验候选 → Skill 提案」导入经验策略评测报告，选择其中的工作范围和目标。生成提案需要至少一个完整配对用例，其中候选策略成功、现行策略失败，且引用了仍有效的已保留候选。同一报告和目标只生成一份提案。

在提案里上传用例 JSON（与上面的 `eval-suite.json` 同格式），点击「运行正文重放」。工作台会选取与提案范围和目标相符的用例，至少一项须填写 `forbidden_reuse`。把任务所需的材料写进 `prompt`。两组使用同一个已配置模型和相同用例，只更换加载的 Skill 正文。没有基准正文时，当前组使用相同输入直接生成。每次调用最多输出 1024 Token，超时 30 秒，整批上限 4 分钟。重放使用独立文本请求，工具、工作区和实时记忆均不参与。

报告记录两组成功率、错误复用、输入和输出 Token、用量覆盖及请求耗时。所有配对必须完成，候选至少成功一项，且每个用例均无成功退步或新增错误复用，才开放「确认生效」。Token 和耗时供发布审阅。重跑会替换上一份报告。确认绑定提案编号、候选版本、基准修订、正文摘要和通过的重放记录。

生效后，新增建议只装配到该范围内目标完全匹配的任务。来源失效或基准版本变更时，运行时会复核并拒绝旧确认。可在同一页面回滚到基准版本，或在没有基准版本时停用。

## 通用 MCP

在「工具与连接」添加可信 MCP 服务并测试连接。stdio 使用程序绝对路径，参数与需要传入的环境变量名逐行填写；Streamable HTTP 支持 HTTPS 和回环 IP 上的 HTTP，Bearer 凭据引用运行环境变量。新发现的工具默认未授权，逐项检查后授权读取，可手动填写 JSON 参数调用，也可交给助手按需选择。

工具定义、协议、连接或凭据变化后必须重新校验授权。输入及输出 Schema 在发现时编译，支持默认及显式 JSON Schema 2020-12、draft-07，不解析外部引用。无法编译或不支持的定义显示原因且不能授权。声明 `outputSchema` 的成功结果必须提供符合定义的结构化内容；失败保留为工具错误，不当作成功来源。

页面与模型共用 16 KiB 结果预览。能在 1 MiB 内完整保存的文本及结构化回执提供下载，并随调用记录备份；超过上限标明截断。连接环境变量值在保存的文本及 JSON 字符串中遮盖。连接检查和单次调用合计最多 12 秒，回执不明时先由用户核对。

首期的文件写入由应用内工作区流程管理。通用 MCP 当前开放经授权的读取，外部服务接入按连接本身的能力与权限验证。后续运维接入再按实际需求设计，不属于本期运行与验收范围。

## 备份与恢复

停止 ClusBot，确认工作区没有其他程序正在写入，再执行：

```sh
./bin/clusbot backup --data-dir ./data/local --out ./clusbot-backup
./bin/clusbot restore --from ./clusbot-backup --data-dir ./data-restored
./bin/clusbot serve --data-dir ./data-restored --demo
```

备份包含 SQLite 中的事项、对话、成果、记忆、连接、已上传原件，以及工作区 `materials/`、`outputs/` 的普通文件和 SHA-256 清单。自定义工作区时，给 `backup` 传原来的 `--workspace-root`。恢复把工作区放入新数据目录的 `workspace/`。

备份与恢复的目标必须为新目录。待核对的文件写入先在原工作台核对；恢复后原待确认写入失效，排队工作等待手动继续，MCP 连接需重新启用和授权。新工作台生成新登录口令，启动 YAML 和环境变量对应密钥需单独保存。

备份和恢复使用当前数据库 schema。恢复备份会停止活跃的周期目标，避免在新数据目录自动恢复触发。
