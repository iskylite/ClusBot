# ClusBot V3.1 前端设计：在对话中把事情办完

**状态：目标规格，未实现。** 业务依据是 [V3.1 设计](../../architecture/v3.1/README.md)、[触发与回执](../../architecture/v3.1/运行时触发与回执.md)及用户提出的对话优先要求。这里不以旧前端、路由和效果图为约束；本文是实现标准，效果图只演示其中一帧，不把待补 API 当成已具备。

**阅读顺序：** §1 看场景复审发现了什么；§2–4 看用户从哪里来、怎么把事办完；§5–7 看设置、后端契约和 A2UI；§8–9 看依赖与通过条件；§10 是视觉与动效验收标准。F 编号对应业务能力，T 编号是独立验收组，BE 编号是后端交付项。

## 1. 按场景复审：先消除前后冲突

不是把所有业务揉成一条演示。以下是复审中影响实现的缺口与唯一裁决；后续章节用同一口径。

| 复审发现 | 本版裁决 |
| --- | --- |
| “对话是入口”被理解为必须有可用模型，但冷启动、审批和故障救援不能依赖模型 | 首页仍是对话。无模型时不承诺自然语言应答，但固定设置、已有任务读取和已签发的明确动作仍可用 |
| “没有原会话也能接续”与“删除对话”之间缺归属规则 | 任务、决定、投递和会话独立。无可用原会话时进系统事项，用同一业务对象续办；无读取权时不显示对象内容，也不会借新会话绕权限 |
| 把所有跨会话信息和授权决定放在一列，会让后台噪音淹没真决定 | 待我处理只收有明确动作的决定和需要人工处置的异常。普通进度更新原卡；不可处理的异常明确责任方，不伪造按钮 |
| “预检通过才开跑”容易和预约已受理、等待资源混为一谈 | 区分不受理、已记录但待决定、已入队等待、满足派发条件。预约只锁定请求约束，不预占未确认的卡；到点重新检查 |
| “暂停”容易暗示正在跑的外部工作也停了；“超时”容易被误当失败 | 模型回复、任务控制、远端作业、资源占用分开呈现。未获远端确认前不报已停止；仍可能被原作业占用的资源不释放，模型或本地执行槽独立回收 |
| “从对话可以配置”容易变成把密钥贴给模型；“选了 MCP 就能调用”混淆作用域 | 对话可启动并回接配置，秘密只用固定安全输入。导入、探测、启用、绑定、授权、派发各有独立状态和回执 |
| “一轮选模型”没有说明是否会改变长期任务 | 先说明覆盖作用域。本轮覆盖不能静默改变会话默认或在途任务；冻结不允许绕过撤权或数据出域限制 |
| 已有场景编号不等于真的测过关键分支 | 每条验收写独立启动条件、可见和后台断言、禁止效果；语义相近但未执行对应边界的案例不计交叉覆盖 |

## 2. 产品壳、操作者与信息架构

### 2.1 默认打开什么，谁能操作

- **左栏是个人助手、查找、待我处理、当前任务和设置。** 一个工作范围默认一条长期个人助手对话，其下可以同时有多个任务。当前任务只列在途事项（包括待审批、等回执），待我处理按独立决定计数；同一任务可出现在两处，读写同一对象，不重复审批。 不以专用工作台、资产库、成果库或工具页作为使用前置。对话显示结论、状态和下一步，详细业务对象按需展开。主要动作一眼可辨，不让所有内容都变成卡片。窄屏用单层详情，返回原消息和焦点。
- **同一个用户可以在不同场景承担不同职责。** 申请者可提交与读自己的工作，值守/审批者只在被授予的范围内处理决定，管理者可维护全局配置与可见性。名称只是用于说明，不是前端硬编码的权限角色；以服务端授权和返回的可用动作为准。无法确定负责人时交给有权限的管理范围，绝不广播资产详情。
- **界面可见不等于可操作。** 设置入口始终可达，但跨作用域数据、审批或有副作用的动作按后端权限。后台任务不要求窗口一直开；服务器离线时显示最后同步时间与暂不可确认的工作。
- **体验底线。** 靠留白、字号和表面层次，不用装饰线；参考资料的浅灰紫、白色和深靛可用于后续视觉，但不改变信息结构。文本/图标说明状态，不能只靠颜色。键盘可完成发送、对象选择、打开和关闭详情；动态更新不抢焦点。支持长中文输入、系统缩放、窄屏及减少动态效果。

### 2.2 消息、对象卡和详情怎么分

| 表达 | 使用条件 | 典型内容 |
| --- | --- | --- |
| 一句话或短答 | 只需理解，不需要保留动作状态 | 普通问答、来源解释、缺项、报告摘要 |
| 对象卡 | 需返回继续操作或活状态 | 任务、资产、等待、报告、连接、计划、跨来源待决定 |
| 详情侧栏 | 信息密度高，需要查证或编辑 | 步骤、日志、版本差异、证据、工具 schema、场景过滤 |
| 独立可信控件 | 明确授权、凭据或高影响动作 | 认证、扩权确认、外发、交付、清除数据、取消影响说明 |

## 3. 对话主链：按真实操作走

### 3.1 单条消息的完整生命周期

1. **发送与持久受理**：输入文字、附件、引用消息、选择的对象和显式临时约束。客户端发送时有请求键；服务端持久接收后才显示“已收到”。断线未知是否提交时先按原键查回执，不能用新键盲重试。“已收到”“已分类”“已建立任务”“已派发”是独立反馈。
2. **理解与定位**：Router 可以拆成问答、只读查询、委托、计划、追问、修订、控制、配置和交付。对象类型和 ID 与正文分开提交。显式任务标签约束本次请求；引用是理解上下文，不得覆盖显式任务标签。没有标签时，唯一可信且可读的候选可用于查询；不可据此直接改任务。浏览侧栏不暗改输入对象。歧义才问一个具体问题；显示对象 ID、范围、状态和可区分依据。否定、条件问句、引用日志或工具描述不发起操作。多项意图分别回执，有依赖的等前项，互不相关的不互锁。
3. **计划和确认**：回显目标、时区/开始条件、资产/能力、计划版本或一次性步骤、不能自动核验的项。权限和动作影响均符合 §3.6 才直接受理，不反复要求批准；新增影响、目标不唯一或事实缺失时只呈现待决定部分。参数或资产变了，原确认不能继续用。拒绝一个分支不取消无依赖工作。
4. **运行和接续**：卡片绑定 Task、Step、Run、Operation、Wait 的具体身份。追问读事实，不重新执行。不用模型回答“是否已经停止”代替真实远端回执。修订只改未派发项，已派发项保留原版本，旧回执不跨代。任务终态不复活；重新跑明确创建后续或新执行代际。
5. **交付与后续**：说明已出结果、可核实覆盖、性能是否达标、资产是否验收四个不同结论，随后给证据和缺项。报告在原对话可更新、展开、下载；保存到本机、按权限下载/导出和向外部收件人发送是三件事；绝不从“帮我写报告”推导发送。用户可在此继续要求更换比较口径、修订下一版计划、与旧结果并列。

### 3.2 四条彼此独立的主路径

1. **普通交流 → 多意图 → 对象确认。** 问“SM 是什么，再查一下 POD7 是否空，先别跑”，直接给解释和只读事实，不建任务。遇同名 POD 时只暂停资产查询这一项，给对象 ID、位置和负责人供选择；独立解释照常给出。选中只作用于这条请求，侧栏切换不隐式改发言目标。
2. **零环境 → 安全接入 → 首次可验收委托。** 尚无模型：固定设置能手工配置和试答。之后从对话登记可信资产来源和 MCP，核对稳定身份、成员、拓扑、管理端点和责任；探测工具能否启动、查找、取证、取消，同步与异步能力分别标识。按需要选择已有方案、一次性计划或保存默认草稿；逐项回报自动可核验/需人工/未接通。只读工具并不发放基准写权限。认证或现场不可达时停在对应步骤，配置成功后回到原诉求。
3. **并行进行 → 追问 → 修订／暂停／取消。** 同会话有基准和另一项任务；修订未派发测项先给差异和受影响依赖。确认前版本若改变，提示重取并保留修改草稿；已发的 J17 仍用原约束取回。用户可停止回复而不改变两项任务；暂停只挡新的派发；远端取消未确认时继续显示运行和占用。后续进展更新原对象而非跳转到另一页。
4. **成果 → 取证 → 交付与再工作。** 跨两次基准结果看单项覆盖、缺失、实测配置、单位和来源。如果口径不同只并列，不生成伪增幅；可提供带缺项的阶段报告。下载由当前权限决定；外发独立说明收件人、内容版本及授权，不从“写报告”推断外发。允许续做缺项或新次任务，但不恢复旧终态或改写历史。

### 3.3 消息、附件与预览

- **消息操作**：悬停或键盘聚焦时显示「复制」「引用回复」「更多」；触屏可长按。复制默认只取正文，代码块有自己的复制按钮。引用支持整条或选中段落；Composer 显示可移除的来源摘要，发送后可从新消息返回原位置。引用不创建新会话，也不等于授权更改任务；一条引用若指向多个任务，不自动选中。删除或撤权时重查权限，显示来源不可用，不保留敏感正文缓存。
- **附件卡片**：发送前显示文件名、大小和上传状态，支持移除或重试。所选文件未就绪时不得静默漏发，可移除该文件后发送。发出后卡片跟在正文下；纯附件不显示空气泡。卡片可预览、下载、引用；任务产物还显示来源任务、测项与核验状态。关掉预览返回发起按钮和原阅读位置。
- **附件尺寸与图标**：气泡内用左对齐的紧凑卡，不拉满气泡。桌面卡片高 52 px、宽随内容收缩，约 168–256 px；多个平铺、空间不足自然换行，长名省略但详情保留全名。先列 3 个，多余通过「查看全部 N 个附件」打开独立列表。卡主体打开预览（不支持则打开文件信息），下载单独操作；触屏命中区按 §10。16/20 px 线性图标按可信类型区分：表格网格、日志横线、压缩包拉链、栅格图片山形、PDF 折页、未知二进制代码符号，同时保留文字。类型未知不通过扩展名打开预览。
- **支持矩阵是产品目标，不是当前后端承诺**：可识别的纯文本、日志、代码、JSON/YAML 分段预览，CSV/TSV 按页表格预览；常见栅格图片可显示缩略图，PDF 用隔离的按页预览。Office、SVG/HTML、压缩包和其他二进制首版只给卡片与获准的下载，不内联或自动解包。未知文件、执行文件、安装包、固件、转储等显示已核实的类型、大小、SHA-256 和来源，不自动打开或执行；告知不能预览的原因。类型以服务端探测为准，文本与单元格作为文字渲染，不执行脚本、宏或公式。超限、扫描待完成或被拒时给明确原因，不用扩展名绕过。大小、页数和片段上限由服务端返回，前端不硬猜。
- **可看不等于能交给模型**：预览、下载、作为本轮材料和交给工具分别授权。用户显式引用后只取必要片段，标出实际页/行与截断范围。图片还需有效模型能力，原始二进制不给模型；经明确委托、授权且存在专用隔离分析器时，可以让工具产生可读摘要。资料授权失效时清理预览、撤掉旧操作，已下载到设备的文件不假称能收回。

### 3.4 Composer：写消息、选对象、看清会发生什么

| 层 | 常用内容 | 行为 |
| --- | --- | --- |
| 上方上下文 | 任务、引用消息、附件、引用证据 | 每项可移除，不把打开的详情当选中。任务显示名称和 ID；正文不变。多来源时区分本轮读取、会话绑定和任务配置 |
| 中间输入 | 多行文本、插入引用、粘贴或拖入文件 | 中文输入法确认候选不发送；保留草稿和发送失败内容；有内容或已就绪附件才可发送 |
| 下方操作 | 添加附件、实际生效的模型默认或本轮覆盖、发送／停止回复 | 默认不挤进技能、工具、策略和运行时整页入口；工具需要显式引用或绑定时由对话唤起受控选择。停止回复只停生成，任务控制留在任务上 |

**T42 怎么选中**：点左栏任务或消息卡的「查看任务」只打开详情。点详情或任务卡的「在对话中引用」，才把「POD7 全套基准 · T42」放入 Composer，聚焦输入且保留已有草稿。也可从 Composer 的对象选择器明确选择。引用一条只关联一个且当前可读的任务消息，可把任务作为可见标签带入；不自动选择重名候选。发送后该消息保留引用，Composer 默认清掉本轮标签；失败仍保留，结果不明按原键恢复。切换窗口、查看其他任务或关闭侧栏不覆盖未发送选择。任务标签不批准、不派发，也不改变默认方案。

### 3.5 修订详情：资产先行，操作只反映当前状态

**显示顺序**：涉及资产 → 本次变更 → 执行影响。首屏显示锁定的资产组和可核实节点/卡数（例如「POD7 · 40 张加速卡 · 节点数未核实」），标「范围不变」也照常展示，可展开实际目标和数据时点；范围有变化时逐项列新增、移除或范围缩小。将本次目标、当前占用和相对于基线的差异分开，不拿动态资产目录冒充任务快照。其下列「集合通信：移除未派发测项」「必测项：3 → 2」；不变的默认方案和保留的既有结果可简明说明。最后说明 DeepEP 是否继续、是否仍占用，依据实际回执。

**强调方式**：资产名与数量用高对比深色；紫色强调实际变更，琥珀色强调占用、待审批或待核实，红色只表示明确的阻断或风险，灰色表示不变。每项有文字与必要图标；颜色不替代状态。外层任务卡保留资产摘要。

**底部只放这个视图的主动作**。普通、可应用且已核验的预览用「应用修订」；关闭面板或返回任务不改计划，入口在标题栏或页签，不与提交并列成模糊的「暂不修改」。仅真有可丢弃的草稿才提供「放弃草稿」。无权或应由他人审批不能显示可点击的应用；有真实申请能力时按契约显示「提交审批」。过期或版本冲突显示原因并提供「重新预览」；无变化则不出现应用。提交中防重复，事件未知查原请求；成功显示新版本并把按钮替换为状态。暂停、取消执行只在任务控制内，不能混入修订底栏。高影响扩展独立说明对象、资产差异与影响，要求相应确认。

### 3.6 通用操作规则：什么时候直接办、问一句、预览或审批

**确认的是新增风险或未明确的选择，不是让用户把原指令说两遍。** 同一套规则用于任务、定时器、资产、报告、模型和工具配置；不根据某个页面是否已经有确认弹窗决定策略。先区分「用户要什么」「现在能改什么」「改了会带来什么」。

| 判定 | 产品行为 | 例子 |
| --- | --- | --- |
| 只查询，或只整理资料与草稿 | 直接给结果；不能因动词、引用或附件内容触发业务动作 | 「停了会怎样？」只解释；「整理成一份报告」生成草稿，不外发 |
| 明确目标、动作、范围，已授权，且操作的真实影响没有超出原指令，当前允许并具有受控恢复路径 | 直接执行并回执；可安全恢复则给对应操作，不额外弹「确定吗」 | 暂停某个定时计划的后续触发；给本次未派发步骤加「暂不派发」标记（若已具备能力）；更改一个不生效的报告草稿 |
| 目标、时间、范围或效果有两种实质不同的解释 | 只问最小缺项；保留已确定部分，无依赖的其它工作继续 | 「别跑第二项」却存在两组测项时，请选哪一组；如果无法判断「先别跑」是等待恢复还是本次跳过，不能自设恢复时点 |
| 动作已授权，但用户没有看过生成内容、接收对象、额外影响，或策略定义为高影响/必须先确认 | 给预览并要求批准具体后果；不问无信息量的「确认操作？」 | 发布新默认方案先展示覆盖范围；外发先对齐收件人、报告版本和数据范围；取消已派发作业先显示已发生效果与清理影响，并应用对应权限与策略 |
| 权限不足或需要独立审批人 | 明确缺失权限或审批人；仅在有授权的申请通道时提交审批。用户说「我确认」不替代权限 | 免除必测项、跨团队释放资源、关闭安全检查不能被「已确认」按钮绕过 |
| 无能力、事实未知、版本过期或远端效果待核对 | 不猜、不假报成功；只在安全可行时进行原操作对账。条件已变化则说明差异，重新评估而不是套用旧同意 | 已进入派发事务就不说「没发」；外发结果不明先查原请求，不重新发；预览期间条件变化则拒绝旧预览 |

**工作从哪一层改变，必须明确写出来**：

- **执行控制**只影响当前对象和执行范围，例如「暂停后续派发」「本次跳过本步骤」「请求取消远端作业」。暂停可恢复，但恢复时要重新检查权限和条件；本次跳过不是让下一次自动运行。暂停和取消都不能顺手改参数、默认配置、通过条件、原始证据或释放未知占用。
- **方案变更**修改步骤、参数、依赖或未来默认，必须分清「这一次」「之后的默认」「共享发布」。生成草稿、应用本次修订、发布默认版是不同动作。即使同一条自然语言提了两件事，也按各自权限与影响分开处理。
- **通过条件与例外**决定结果能否验收。「本次未执行」不等于「已通过」「免测」或「不再必测」。若仍缺必测项，报告保留原要求并标缺项；免测或替换证据必须有单独的政策、权限和原因，不能借编辑计划默默重算通过结果。
- **外部副作用**从申请到核实单独记状态，例如「取消已请求／远端已确认取消」「外发待送达／已送达」。本地回执只能证明本地受理或阻断；不可从它推断远端完成。

**谁判定和如何生效**：AI 只提出结构化候选（目标引用、动作、仅本次/未来、用户原文依据），不签发权限，不能把日志、引用、假设或建议冒充用户指令。固定控件可以直接提交同类候选。Go 按动作声明的允许范围、事务守卫、影响和审批策略判定，权限、对象版本、执行代际、当前状态、真实能力和幂等键均需校验。运行时在同一事务比较未派发/已派发并记录实际结果；若派发先赢，不自动升级为取消。需要确认时把提示绑定到动作、目标、版本、影响与有效期；重试核对原请求、审批以后仍按最新状态重验。回执写「已做、没做、待核对」，可逆动作提供有准确语义的下一步；不存在撤销能力就不显示「撤销」。

**研究依据**：[Google 会话确认](https://developers.google.com/assistant/conversation-design/confirmations)区分显式确认与在回执中回显理解；[Microsoft HAX](https://www.microsoft.com/en-us/haxtoolkit/guideline/scope-services-when-in-doubt/)建议不确定时缩小动作范围或澄清；[Apple HIG：Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts.md)不建议常见可撤销动作反复弹窗；[GitHub 环境审批](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/review-deployments)展示发起和按策略审批分离；[Kubernetes CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/#schedule-suspension)与[Temporal 取消](https://docs.temporal.io/develop/go/workflows/cancellation)分别展示暂停未来执行不能改已经启动的作业、发送取消请求与确认取消的不同。上面的运行时守卫是 ClusBot 自己的设计，不是把任何一个外部产品照搬进来。

**动作名称必须包含对象层级或实际效果**：例如「暂停后续调度」与「请求取消当前作业」，不要共用含糊的「暂停」。同为 Kubernetes，[暂停 CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/#schedule-suspension)保留已启动的 Job，而[暂停单个 Job](https://kubernetes.io/docs/concepts/workloads/controllers/job/#suspending-a-job)会删除活跃 Pod；这正说明不能从按钮动词推断真实影响。T17 要让停发与派发竞争：停发事务先提交时，真实派发调用为零、原必测项仍保留；派发已占先或效果未知时，保留原操作与可能占用并对账，不自动发取消，也不回执「已拦截」。验收用提供方替身核对调用次数与状态，而不是只检查文案。

**展示与回执**：执行控制已生效时，对话给实际回执并链接「执行记录」，详情显示作用范围、当前占用和不受影响的工作；不再同时出现「应用修订」。执行控制处于未知、仅受理或需要特定权限时只呈现事实与可用下一步。真正变更步骤定义、默认方案或通过条件时，才进入相应的预览或审批流程，两个视图不能共用成功按钮。

**首个确定性动作：本次跳过一个未派发步骤**。任务详情从服务端拿当前版本、稳定步骤 ID 和可用动作；只在本次目标清楚且允许时显示「本次跳过」。提交带当前方案修订号与请求标识；按钮即明确操作，不再弹「应用修订」。提交中只禁用该操作；服务器返回已生效才更新执行记录。状态或版本冲突时刷新、提示真实原因，不自动重试。网络未知先查原请求状态；同一请求重放必须保持原请求标识。对话发起同动作时，只有目标与动作被明确识别、Go 已通过同一准入并返回实际结果，才可以说「本次已跳过」。缺少能力时不显示成功，也不把普通续聊转成方案删除。

**当前落地边界**：明确的「本次跳过」与专用会话指令已接入独立执行控制，不使用删除测项替代。选中任务并在专用入口自由描述时，模型只生成待确认建议，界面显示实际动作和测项，再由 Go 重验确认；普通聊天不附带执行意图。方案修订仍走「预演→应用」。独立暂缓/继续、验收例外、全量附件在线预览和现场作业未因样稿而上线。

## 4. 非对话工作和业务完整性

### 4.1 系统事件如何变成人可以接手的事项

后端先分类并去重：**定时到期**依配置产生一次有限任务；**可信回执**匹配原任务/代际或留待对账，不新建任务；**外部观测**先记录事实，只有满足已发布规则和授权才可能触发工作；**需要人工决定**才登记待办。自主继续不等于发了通知，更不等于同意。来源是系统就标系统，不伪造用户话语。

| 来源情况 | 用户从哪里接手 | 状态如何变化 |
| --- | --- | --- |
| 原会话仍可读 | 更新原对象卡；确需人工处理才加待我处理链接 | 已读/稍后不解除等待；决定生效后更新原卡 |
| 原会话归档但授权仍有效 | 待我处理中打开原对象；不自动恢复归档，不强制新建会话 | 归档不停止任务，继续交互可选择在可写会话显式引用 |
| 无会话或原会话删除 | “系统事项”承接同一对象 ID，显示来源、责任、时效和证据入口 | 不复制旧正文，不破坏业务审计；旧引用明确失效 |
| 无权读或决定已失效 | 不返回详情；有权看状态时只给受限提示与下一步 | 不缓存敏感正文；过期、撤权、他人已处理都重取权威状态 |

通知与待办分开：待投递、已投递、失败只按渠道回执；未读、稍后、解决是用户处置。重复事件归并但不吞独立对象；静默时段只影响通知，不取消原任务或审批截止时间。批准、拒绝、待补材料由固定控制向同一后端确认，模型离线时也能完成。没有现行授权的外部接触或敏感发送不自动发生。无模型时只能处理已知对象和已签发的明确动作，不把自由输入重新分类，也不授予新权限。

## 5. 全局设置、会话绑定与故障救援

**模型提供方配置可用连接，模型档案声明能力，策略决定使用，权限决定可做什么。Skill/MCP 能装进全局，但必须区分启用、会话选择、任务冻结和操作授权。**

| 区域 | 必须能做的事 | 生效规则 |
| --- | --- | --- |
| 提供方和凭据 | 多连接、协议/地址、本地/远端、认证、超时、停用、轮换、接通检查 | 拆测试连接、认证、列模型和最小实际应答；列不出仍可手填。只支持已实现的协议；系统注入显示出处不回显密钥。验证与开为默认是两件事 |
| 模型档案 | 模型 ID/别名、上下文和输出预算、图片/文件、结构化/工具/流式、推理档和实际限制 | 区分提供方声明、探测、手工覆盖、未知。未知不假设支持，只有支持才传推理参数。保存前显示生效值和影响 |
| 角色策略 | 普通对话、Router/计划、执行解释、报告可继承全局或分别配置；预算、并发、回退、数据范围 | 新请求：硬权限/预算/数据边界 → 显式本轮 → 会话 → 角色默认 → 全局；在途工作读冻结版本。撤权优先于冻结。不同提供方、额外成本或数据出域不无声回退 |
| Skill 目录 | 导入来源及指纹、校验资源、版本、启停；查看摘要并按需展开正文、引用；创建/复核经验提案 | 导入≠执行脚本，启用≠调用权限，绑定≠发布计划。可选择本轮/以后此会话/此任务；任务锁定引用，禁用后不新读或执行 |
| MCP 目录 | 登记、认证、握手、工具/资源与 schema 探测、变更、停用和审计；连接凭据与本机进程启动分别审批 | 已连接≠有权调用；绑定范围包括连接、工具、用途、目标与时效。步骤的能力映射另有版本。变更默认不改已执行，漂移需回审；只读取证和取消可有独立权限 |
| 外观、环境、数据 | 语言、时区、主题、快捷键、无障碍、通知偏好；工作区/网络和本机执行限制；保留、导出、清理、审计 | 提示影响、来源、是否需重启；必须可在无模型时进入。配置冲突保留草稿，支持回滚到有效版本；诊断分别显示实际模型、时延、可知用量、缺口，不泄露秘密或内部推理 |

配置工作链：在对话内创建草稿→必要时通过可信安全表单输入凭据→验证/预览→保存/启用→返回原对话明确“仅本轮”“以后此会话”或“给此任务”，再重新核验权限。解绑只改作用域，不卸载共享连接、不取消在途操作。没有可用模型时，用设置里的固定入口完成同一配置链。

### 5.1 配置的状态、覆盖和救援顺序

每项都要能看见草稿、验证通过或失败、已生效、被覆盖、已停用/失效。账户级、工作范围、角色默认和本轮设置均显示实际生效来源。保存失败先保留原配置；输入未提交可保留草稿，但秘密从不进入通用草稿。试连不默认启用；切默认不改既有任务；编辑时若发现服务端版已变，展示差异请复核而不是静默覆盖。恢复旧版后再次检查权限、能力与数据范围，不能借回滚恢复已撤销凭据。

### 5.2 Composer 模型选择的语义

- **默认文案「使用默认」**，附近显示当前有效模型或在菜单内显示来源；只有配置了真实的角色策略和多个可用候选，才显示「按策略选择」。停止使用「自动选模型」这个没有交代来源和作用域的名称。自定义选择必须明确标「仅本轮」；如果当前只有一个有效模型，直接显示名称，不画假下拉；无模型提示「配置模型」。
- **策略不是让模型自己挑模型**：后端先筛出符合权限、数据出域、能力和预算的候选，再按显式本轮覆盖、会话、阶段/角色默认及全局策略取匹配项。不会因当前任务有附件就擅自换供应商；不符合时给原因和可行选项，不静默绕过。没有验证的视觉或工具能力不得标可用。
- **回执写实际使用结果**：如本轮选了一个模型，只覆盖策略允许的本轮生成角色；Router 和后台 Worker 可使用各自策略，查询固定状态可完全不调用模型。界面报告实际使用的模型/阶段及已允许的回退，未使用就不显示虚假模型。选项不修改会话默认、不替换已冻结的后台策略、不暂停或取消当前任务。

## 6. 前后端契约：界面只表达事实

### 6.1 状态与动作的对应关系

| 同时发生的事实 | 对话用语 | 可做与不可做 |
| --- | --- | --- |
| 请求已发送、受理未知 | 提交待确认，查询原请求 | 允许查状态、按原键恢复；不能写已入队 |
| Task 已受理、尚未派发、资源不够或资料陈旧 | 已受理；等待具体资源/现场复核 | 可看依赖、调整未派发部分；不能显示远端执行中 |
| 等待时间/人工/依赖 | 等到时间、等指定决定、等依赖 | 真正满足的纯时间等待可重评；人工与外部超时不自动通过 |
| 已派发且响应丢失或迟到 | 远端效果未核实、下次核对时点 | 先查原作业。除非确认未执行，或提供方明确保证同键重交无重复效果且运行时复核许可，否则不重交；前端不自行发新键 |
| 任务暂停，远端仍跑，模型已释放 | 已停止新派发；作业仍在运行，资源仍占用 | 可查并按授权处理远端；“停止回复”只管本轮生成 |
| 已申请取消，夹有迟到有效结果 | 正在核对是否已停，显示实际影响 | 原作业仍可能占用时不释相关资源，不报作业已停；结果仍可入账但不得复活任务 |
| 已取得结果但缺证据或阈值 | 指标收到/部分已核实；未证明达标 | 可查缺口、验证原件；不强行转绿 |
| 权限、版本或动作到期 | 状态或权限已变化 | 旧卡只读或裁剪，拉最新再决定；不重放旧确认 |
| 模型离线但运行时可读 | 生成不可用；可查任务和设置 | 固定读取、决定和有权限的控制仍可用 |

### 6.2 目标接口契约（精确路由待后端落实）

- **对象快照**：类型、稳定 ID、版本、状态分量（Task/Step/Run/Operation/Wait/租约/证据与审批分别给）、采集时间、来源引用、机器原因码与可读原因、允许动作和禁用理由。详情按权限分页，秘密永不进入响应。前端用事实编排表达，不另造业务状态机。
- **动作**：使用服务器计算的动作引用，绑定 actor、目标、当前版本/执行代际、约束及期限；带请求键和允许的输入。区别返回已受理/已应用/已拒绝/待核对。「禁用」只是展示，后端重验；相同键相同内容只应用一次，内容不同报冲突。后端无能力时明确返回，不给假按钮或悄悄授权。
- **消息与业务事件**：消息带稳定消息 ID、会话、原始来源和对象引用；持久业务事件带游标与对象版本，和模型临时文本流分开。重连从游标恢复，过期拿快照；去重并拒绝倒退状态，历史回放没有副作用。对象越权时客观提示当前不可见，不把受限内容留在旧缓存。
- **消息材料和影响范围**：请求分别携带引用消息/片段、任务对象、附件/证据 ID 及会话模型覆盖，不从正文猜授权。预览需返回资产快照和当前占用、差异与适用动作；材料接口区分上传状态、预览/下载/用于模型的授权、类型与大小上限、服务端可读预览模式。
- **待办/通知**：查当前主体可见的待办快照、查询来源、标读、处理后显式更新以及重复归并；状态与 Pending Decision、实际通知投递和审批审计分别记，不能把已登记当已提醒。
- **前端可靠性**：草稿、待发送请求键与选中对象可恢复；阅读位置以稳定消息加局部偏移保存。翻旧消息只显示新消息提示；切 App、缩放、开/关详情、重连不跳顶。旧网络响应不得覆盖新对象；窄屏全屏详情关掉回原消息和触发焦点。日志和大表惰性加载。

### 6.3 复合状态不覆盖彼此：示例与裁决

以下是人会看到的一组信息，不是新的前端状态枚举：

> POD7 基准 · 已暂停新步骤。DeepEP 作业仍在运行，40 张卡仍占用。下次核对 21:30。
>
> 可以查看作业或在已有授权内申请取消；不可直接重跑。助手回复暂不可用不影响以上状态。

- 接口结果明确哪层更新：同一次事件可改变 Operation，但未必改变 Task、验收或租约。派发应答未到，历史卡只显示最新可信时点；“超时待核实”和“远端确认终态”分别取证。
- 真正改动的动作都返回目标版本、一致的接受/拒绝原因和查状态的引用。确认过期、版本冲突、权限撤回和缺能力分别提示；只在有相同受理键时可重试提交，普通网络重试不等于可重复业务动作。
- 审批、待办、报告都按后端授权读取；隐藏字段不能靠 React 事后遮住。撤权更新到已打开的侧栏、历史缓存和 A2UI（重新裁剪或清空）。解释中展示材料来源、缺项和截断范围，绝不展示内部思维或凭据。
- 活动中的本地草稿、不可确认请求、详情与历史锚点分别保存。浏览旧消息时只提示新消息；用户发送/明确点击跳到最新才移动。窗口失焦、切 App、重连后恢复的是当前视图，不会逮住旧请求把另一对象覆盖掉。

## 7. A2UI 1.0：把业务状态与表现解耦

采用 [A2UI 1.0](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/)作为可选展示层，用[官方 React 支持](https://a2ui.org/renderers/)和[自定义目录](https://a2ui.org/guides/defining-a-catalog/)。能做复杂编排：例如一个资产对比 Surface 中用列布局、分组与标签组合受控表格、关联证据和筛选；不能让模型临时生成整个工作台、任意网络操作或业务状态。组件与动作：

| 类别 | 首批支持 | 边界 |
| --- | --- | --- |
| 基础目录白名单 | 文字、图标、行/列、卡、列表、标签集、非敏感文本、选择、日期时间、有限按钮 | 适合摘要、选项、小表单和页签；不授予任意链接、媒体、路径、RPC 或命令 |
| ClusBot 扩展 | 状态标签、对象引用、属性表、指标比较、证据清单、筛选、差异预览、只读工具预览 | 自定义组件可有分页、虚拟化、数据可访问性；只接经过权限裁剪的字段和有界对象引用，不让模型制定任意数据地址 |
| 固定 React | 对话壳、业务状态卡、Task/审批/取消控件、凭据、设置、长日志、浏览证据、空态和恢复 | 模型或协议不可用仍可使用。授权确认不可由动态布局设计文案或自行选择目标 |
| 后续 | 受控拓扑、图表、复杂报告片段 | 一个复杂受控组件优于生成数千节点；能降级为数据摘要，不能挡原任务 |

Go 提供事实和允许动作 → 模型建议布局 → 两端校验组件/字段/绑定/环/规模 → React 渲染 → 回传最小、白名单动作 → Go 按 §6 再校验。模型不能给自己签发权限。按[协议消息](https://a2ui.org/concepts/messages/)，打开 sendDataModel 会回传整个 Surface 状态。默认关闭，凭据完全在固定安全表单和专用端点，不进动态数据、日志、SSE、聊天或模型请求；用合成凭据检查真实出站内容。未知类型、版本或数据局部错误，仅降级该 Surface 至文字或固定卡片。

### 9.2 哪些必须拆开跑

- **普通问答、零接入、已有条件的下单**是三个不同起点。只读接入成功不得作为写动作通过的证据。远端执行没有可追踪身份或原件时，明确不可自动验收。
- **审批、外部回执、定时计划**各有独立到期和恢复用例。用基准预约不能代替周期计划的编辑、停用、漏跑；拿到本地回执不能代替外部效果证据。
- **偏好和 Skill**分别验：偏好的本轮/持久、来源撤回和派生失效，不能以 Skill 提案通过替代。**验收、报告生成、下载、外发**分别验，不拿完成一个动作推定其余权限。
- **真实中文输入法单独验收（T15 子例）**：在打包的 macOS App 和支持的浏览器中，显式选中 T42，使用系统中文输入法输入「把本次尚未派发的单机带宽改为 90 秒」。用回车确认候选词，不得发送请求，草稿与 T42 保留；候选面板中的 Esc 不得清除 T42 或关闭应用详情。再明确点「发送」，服务器只收到一条关联 T42 的消息；返回方案预演，不写入修订，另点「应用修订」才提交。用开发中实际支持的宿主记录行为，不能只靠合成键盘事件或 `isComposing` 推定通过：[WebKit 的组合事件顺序报告](https://bugs.webkit.org/show_bug.cgi?id=324380)说明部分宿主中候选确认的回车可能出现在 `compositionend` 之后，该报告不是 ClusBot 已复现的证据。
- **客户端和后端都要验**：Go 查越权、状态迁移与持久结果；前端查键盘、动态焦点、断线重连、降级显示；至少一种大列表和长历史。仅检查文案或静态样式不能确认业务闭环。

## 10. 界面规范：同一语义用同一组件

**适用范围**：个人助手、任务详情、文件预览、设置和 A2UI 扩展展示。日后的前端实现把下列值放到同一套设计变量和共享组件里；页面和 A2UI 不自定义一套尺寸、阴影或动效。主页 SVG 是明亮主题的静态样板。其余场景 SVG 只画相关组件及必要联动，不复刻公共导航，不把演示文字放进产品界面；样稿不代替组件状态和交互验收。

| 状态 | 运行/已核实 `#145E59` / `#E7F5F0`；待处理/占用/待核实 `#7C4C0A` / `#FBF0DA`；变更 `#573C83` / `#EEEAF8`；阻断/危险 `#8B342D` / `#FCEDEA`；中性/不变使用次级文字。颜色旁要有状态文字，不用绿色标只收到了回执的状态 |
| 字体 | 系统无衬线，中文优先系统中文字体；日志、代码和需要对齐的 ID/数值用等宽或表格数字。单位跟数值同行；关键内容不截断，无空间改为换行或逐层展开 |
| 字阶（字号/行高，粗细） | 页面标题 24/32·700；侧栏标题 20/28·700；区块或卡片标题 16/24·650；对话/输入正文 16/24·400；按钮、列表和字段 14/20·600（解释正文 400）；时间、来源、状态等辅助信息 12/16·500。辅助信息不能代替主正文，不使用更小字号解释重要规则 |
| 尺寸 | 内容间距只用 4、8、12、16、24、32；图标用 16 或 20；响应式变化改排列和换行，不靠缩小字号塞下内容。每段长文保留原文结构，错误优先说原因和恢复方式 |

### 10.2 按钮、链接和标签

| 组件 | 样式与用途 |
| --- | --- |
| 主按钮 | 深靛实底，白字，圆角 12，高 40；需要强调的表单/侧栏主动作为 44。一个操作组只有一个主按钮，例如「应用修订」；聊天「发送」和右侧「应用修订」是两个独立操作组 |
| 次按钮 | 淡紫实底，高 36，圆角 12。用于「查看任务」等次要导航，不与主按钮争同一决策 |
| 安静操作 | 鼠标、键盘可达的文字或图标，桌面命中区至少 32 × 32，圆角 8；例如「复制」「引用回复」「更多」「预览」「下载」和关闭。纯图标要有可访问名称；触屏命中区至少 44 × 44，不靠悬停才出现，拖拽必须有点选替代 |
| 危险动作 | 只有明确破坏或不可逆时用危险色。取消作业与关闭面板不是一类；高影响确认说明目标、范围和实际结果，使用动作动词，不写空泛的「确定」 |
| 状态标签和链接 | 标签优先用文字，默认高 28、圆角 8，无点击外观时不放箭头。可移除的任务/引用标签有独立移除命中区。导航/下载/外部地址用链接语义，提交/复制/开面板用按钮语义 |

**共同状态**：默认、悬停、按下、键盘焦点、禁用、提交中都从组件得出；悬停/按下只改表面色，不跳动；键盘用 2 px 高对比焦点环、不被侧栏裁切（不是装饰描边）。不可用且需要解释时，原因放在相邻文字而非只有 tooltip；提交中保留原宽度与操作对象，用「正在应用」等真实状态，不能假报成功或允许二次点击。已有结果可重取；结果未知按原请求核对，不造失败提示。所有破坏性动作都不设为 Enter 的隐式默认。

**详情里的跨区操作按结果定层级，而不是按位置定样式**：

| 操作 | 用什么控件 | 点击后的结果 |
| --- | --- | --- |
| 查看任务、打开资产清单 | 展开行、链接或次按钮；按当前布局择一 | 只打开详情，不能改变 Composer 的目标或发送内容 |
| 在对话中引用 | 弱强调文字按钮 + 16 px 图标，无底色、无描边；标题下的状态行右侧，业务页签之上。使用 14/20 字阶，命中区遵循安静操作标准 | 将带名称和 ID 的对象加入 Composer 并聚焦；不发送、不授权、不改对象。若已引用同一对象，改显示「回到输入框」并只聚焦；若改选另一任务，保留正文并明确显示新的目标 |
| 应用、批准、提交 | 仅该视图的主操作可用实底主按钮，用业务动词命名，例如「应用修订」 | 只有明确动作才写入，按服务端版本和授权重新校验；关闭或返回始终不提交 |

标题下的状态行左侧只陈述事实，不可点击，右侧才是可操作文字。正常作业显示「运行中」；当本地已暂停且远端仍在跑，才同时标「已暂停 · 远端仍在运行」。不允许悬停时才出现引用入口；宽度不足时优先显示完整状态，动作退到下行，不缩成含糊图标。窄屏引用后回到对话并聚焦 Composer，键盘可操作。不能用状态样式伪装动作。

### 10.3 卡片、表面与阴影

- **圆角只用 8／12／16／24**：标签与轻量工具 8，按钮/附件 12，气泡、对象卡、分段信息组和 Composer 16，外壳/大面板 24。按钮圆角不跟按钮宽度变化，不做一会儿胶囊一会儿方块。
- **卡片主要是三类**：用户消息气泡，业务对象卡，附件/证据卡。采用同一内边距 16，嵌入附件和紧凑状态区可用 12。业务卡顺序为标题和状态 → 对象/资产摘要 → 事实 → 主入口。右侧资产、变更、执行影响用同一种分段表面，只有重点标签、数值和风险变色。只读卡不放不可用的假按钮，不用每条消息都包卡。
- **默认无阴影、无装饰边线**。靠底色、间距和结构区分。外壳示意阴影统一为 `0 12px 24px rgba(50,38,77,.10)`；真正浮出内容的菜单/弹层只用 `0 6px 16px rgba(50,38,77,.12)`。消息、任务、附件、侧栏分段与固定 Composer 不加阴影。图标必要线条、焦点环及高对比模式边界不属于装饰线。

### 10.4 动效和实现验收

| 反馈 | 标准 |
| --- | --- |
| 悬停、按下、色彩反馈 | 120 ms，仅颜色/透明度变化，无缩放 |
| 菜单、工具条、提示显隐 | 160 ms，透明度；关闭动作不等待动画才释放焦点 |
| 详情面板进出 | 200 ms，透明度加不超过 8 px 的位移；窄屏保持当前阅读锚点 |
| 运行中、加载中、更新结果 | 选用统一的静态状态加真实进展。只有短时未定进度可用轻量指示，不给在途卡反复呼吸、不对持续日志、流式文本做逐字动画；后台更新不抢光标和焦点 |

进入使用 `cubic-bezier(.2,.8,.2,1)`，退出使用 `cubic-bezier(.4,0,1,1)`。系统启用减少动态效果时禁用位移、缩放和循环动画，状态立即切换或低幅度淡入，不靠动画传达办理结果。焦点返回发起控件，等待和错误通过读屏可读状态反馈（避免逐字播报）。

以 [Apple HIG：Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons.md)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion.md) 和 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 为依据；上面的时长、字号和命中尺寸是 ClusBot 产品标准，不是外部规范逐条规定。实现验收至少覆盖：小文字对比 4.5:1、大文字和关键控件状态 3:1；颜色之外能区分状态；Tab 顺序、焦点恢复与不被遮挡；桌面和触屏命中区、长中文与 200% 文字缩放；普通、禁用、提交中、未知、失败各状态；系统减少动态效果打开时，停掉转场也能完成同样任务。SVG 只验外观与静态色对，不把静图当作可访问性合格证明。
