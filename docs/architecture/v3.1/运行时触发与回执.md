## 1. 谁定义下一步

| 场景 | 绑定于哪份配置 | 重放时怎样识别同一次 | 不满足时 |
| --- | --- | --- | --- |
| 每日发现 | S7 当前已启用；记录时区、计划时点、方案版本、目标范围和执行主体；首期错过的历史周期可记跳过，不集中补跑 | `schedule_id + scheduled_at_utc`。修改配置不让同一计划时点再创建一件；旧版本未领取的事件重新校验 | 已禁用、授权过期、超出有效时间：记录原因，不派发 |
| J17 回来 | 已登记的 O9、来源连接及作业号、T42 步骤代际、当前 Wait 版本；下一步来自 T42 保存的流程版本 | 外部消息按可信来源与事件 ID 去重；同一作业终态也可经轮询到达，最终由当前 Wait 版本的原子状态变更消除重复推进 | 归属不明则隔离/待关联；旧代际留证，不推进当前任务 |
| 发现新资产 | 观测由领域服务处理；「已纳管」是领域提交后产生的事实。已发布触发设置明确监听哪种迁移、适用对象、创建哪个工作方案、使用哪个主体 | 观测按来源事件去重；后续任务按触发配置与已提交的迁移身份去重，不按 IP | 未核实保留候选；没有后续设置时只记事实；未获授权不创建可执行任务 |

等待截止时间产生的是针对**已有 Wait** 的事件，不是周期计划。截止消息只能把该 Wait 推入超时处置/对账分支；之后可信结果仍可登记，是否继续由当时的任务状态、代际和对账策略决定。

## 2. 哪些记录必须一起写

1. **周期到期**：事件键和到期推进同一事务，或具备可验证的等效补偿。不能先标定时器已送达，再独立写 Inbox；两步间崩溃会丢唤醒。消费事件时，把事件处理结果和唯一的任务创建结果同事务保存。
2. **派发前**：检查授权、现场事实及租约；把 Operation（含 O9、幂等键、任务和步骤代际、连接与参数指纹）及待派发记录原子写入。取外部许可、做网络调用不占写事务；执行网关临发复核。重启不能仅凭本地「曾尝试发送」判断远端有没有执行。
3. **回执入站**：验证来源和消息格式，保留原始摘要，按可信来源＋事件 ID 持久保存，成功提交后才确认接收。相同键和相同内容为重复；同键不同内容隔离审核。早到的可信回执先留下，绑定 J17 后重查。来源验证规则由适配器固定，不相信正文自带的任务 ID。
4. **唤醒与后继**：在一个短事务中校验当前代际，原子关闭匹配的 Wait、保存对账/操作状态、登记后继工作和处理结果。后继工作只表示可以取证或核验；「远端作业结束」不直接把 Task 或资产写成通过。
5. **领域变更**：领域服务在自己的事务保存有来源的资产事实或纳管迁移，以及可靠待发送记录；运行时消费此事实并检查触发设置。跨服务时不假设它们共享数据库事务，两边用稳定 ID 重试与核对。

6. **停发与竞态**：在与派发登记同一写事务边界核对主体、目标、版本、代际以及原 Operation 是否仍未创建；停发写执行控制、原因和可回放回执，不删除步骤、不改变依赖或验收要求。若派发登记先成功或效果未知，沿原 Operation 做查证，保留可能占用；不可从「不再派发」推导「取消在途」。
7. **明确授权与额外审批**：可以直接办理的有权动作不用第二次确认；有不同效果、强制审批或额外影响时才暂停对应分支。确认引用绑定当前动作、对象、版本和期限；请求重放返回原回执，不能创建新动作。无业务能力的专用任务不回落到普通模型 Worker。

**单步骤执行控制的首批契约**：对象引用是 Task + 运行时 Step ID，不从列表下标、展示名称或模型文本推定。用当前方案修订号、请求键和经过校验的原因提交；只允许尚未登记操作的 queued 步骤。本次跳过保留计划版本、必测基线、已存在的证据与占用；涉及该步骤的硬依赖继续按未核实处理。回执持久记录动作与实际结果，当前能力不支持的暂停、继续、取消或豁免不能自动降级成别的操作。

## 3. J17 如何与 T42 对上

1. 绑定冻结到本次执行：哪家连接、哪个测试工具与契约、要交付什么证据。把范围和参数转换成工具请求；凭据只给网关。
2. 提交应答带回 J17，同一事务保存 `(已绑定连接, J17) → (O9, T42, Step, 执行代际)`，并创建或确认对应 Wait。轮询和推送都走同一组关联检查。
3. 若提交应答丢失，先用调用前登记的幂等键查同一服务。能确认已受理则接回原作业；不能确认则保留待核实。只有提供方可核实没执行，或明确保证按相同键重发不会重复产生外部效果，才受控继续。
4. 匹配回执后从同一作业取结果清单或可信输出。只有已绑定的来源、作业与测项能明确对应，才交给版本化核验器。配置不符、证据缺失、格式无法核验分别记录。AI 可写解释，不以解释覆盖核验结果。

## 4. 最低故障验收

| 注入条件 | 必须查看的结果 |
| --- | --- |
| 到期写入前后重启；同一时点送两次 | 不会丢本次唤醒，最多一件同键任务 |
| J17 回执早于本地绑定；随后同一终态又被轮询到 | 绑定后能对上原任务；只登记一次后继 |
| 已派发但应答丢失；提供方查不到原作业 | 不重新提交无幂等保证的动作；显示待核实 |
| 等待超时和完成回执竞争；取消后回执迟到 | 不误报远端失败；不让旧代际恢复执行，保留证据供核对 |
| J17 有指标、缺方案所需的作业关联原始证据 | 显示「指标已收到，原始证据缺失」；不计为已核实 |
| 只发现一个新 IP；或已纳管但没配置检查/已撤权 | 只记录候选或事实，不启动未经授权的操作 |
| 停发与派发登记争抢同一未派发步骤 | 停发先赢时外部提交次数为零、必测仍在；派发先赢或结果未知时保留原 Operation、Wait 与持有，不自动取消或误报已拦截 |

## 本机只读执行的租约恢复

运行时定期回收已过期、无 Operation 和结果回执的本机嵌入资产验收读取；每轮上限 16，按最早过期处理。回收和重置同时核对工作与租约代际，重新领取后拒绝旧回报；空轮不写状态或审计。不扩大到真实外部操作或结果未知的动作，这些仍按 Operation 对账，不能据租约过期推断远端未执行。已通过模型关闭、超过单批、旧回执迟到和对账状态不变的本机测试，不代表任意工作都能自动恢复，也不代表真实现场容量。

基准队列用测项入队、修订或依赖就绪时间与已有 Operation 的到期时间一起排序，不能把“当前可派发”的零值当成最早日期。新任务持续入队时，已到期的旧作业仍能用原请求核对；只有核实终态才释放占用，不会因此重复提交或提前查询。

手工回收和启动恢复也不能把过期动作重新放回可领取队列。仅精确关联同一任务和步骤的在途 Operation 才进入待核对，并按操作去重计数；若没找到对应记录，则保留动作现场供核查，不把缺记录当作未执行，也不影响同任务其他步骤的操作。这里没有新建通用外部重试入口。
