# 集群趋势接口

`GET /api/v1/domain/cluster-trends?range=7d` 用于取得在役率和新增故障片段的时序数据。`range` 支持 `24h`、`7d`、`30d`，默认 `7d`；其他值返回 HTTP 400。接口要求已登录，多人模式使用当前账号的业务库，并只统计请求时对节点具有有效 `read` 对象授权的数据。撤权后连同历史数据一起停止展示；无权节点及其故障数量均不返回。

## 时间与节点

所有时间为 UTC Unix 毫秒。`24h` 返回 24 个按小时对齐的桶；`7d` 和 `30d` 分别返回 7 个或 30 个按日期对齐的桶。时间桶左闭右开，包含当前未结束的小时或日期；最后一个 `end_at` 比 `computed_at` 多 1 毫秒，以纳入计算时刻的记录。桶中节点数量取该桶结束时的状态，当前桶取计算时刻的状态。故障数按故障片段 `window_start` 所在桶计数，不按活跃时长重复计数。

`total_nodes` 是该时刻已经登记、当前类型为 `node`、`计算节点`或 `GPU 节点`且请求时有权读取的节点数；包括借出和退役节点，不包括卡、网卡等部件。节点类型本身没有历史版本，按当前登记类型判定。`in_service_nodes` 是其中最后可确定状态为「在役」的节点数；若存在不能确定的节点，`unknown_nodes` 会列出数量，`in_service_percent` 为 `null`。没有节点时百分比也为 `null`；否则为在役节点数除以全部节点数乘以 100。

状态重建使用资产登记/更新历史、状态迁移以及借出和归还记录。部分旧写路径没有完整记录，因此数据可能缺失；检测到最新历史状态与当前状态不一致时，无法确定的区间标记为未知。并非每次缺失都能检测出来，响应的 `state_history_basis` 为 `recorded_events_may_be_incomplete`，不能将这些数字视作完整的历史审计记录。

## 故障分类与覆盖

`fault_categories` 固定为 `nhc`、`oob_alert`、`network`、`service`、`other`，`fault_counts` 提供每个类别的计数。它们是来源观测类型，不是设备类型或已证实根因；旧格式的指标名称或未知类型归入 `other`。`fault_count_basis` 为 `segment_start`，`fault_category_basis` 为 `observation_kind`。

故障表未独立保存节点和类别。接口优先使用 `observation_refs` 指向的持久观测记录：所有引用均能解析到同一节点，且可识别的故障键与该节点不冲突时才计入。这样可识别包含冒号的节点和来源，也可识别有观测引用的旧 `节点/指标` 格式。引用中有已解析但又缺失或跨节点的记录时，该片段不计入；没有任何可解析引用时，只接受恰好为 `来源:节点:类型` 三段且三段均非空的键，不以可授权节点的名称后缀猜测归属。其余故障不会出现在计数中，接口不泄漏无法归属或未授权片段的数量。响应 `fault_coverage` 为 `consistent_observation_refs_or_simple_keys`；因存在未纳入的片段，零值不代表环境中确认没有故障。

每个桶的主要字段为 `start_at`、`end_at`、`total_nodes`、`in_service_nodes`、`unknown_nodes`、`in_service_percent` 和 `fault_counts`。响应另有 `range`、`timezone`、`bucket_unit`、`computed_at`、`node_count_basis`、`fault_source_status`（`live` 或 `not_connected`，当生产库尚未接入故障片段写入时为 `not_connected`）以及上述统计口径字段。
