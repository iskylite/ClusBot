# ClusBot V3.1 前端设计：在对话中把事情办完

**状态为功能测试版，视觉方案和 SVG 尚未定稿。** 本文记录当前功能契约和目标规格，按实际接口可用性验收。业务依据见 [V3.1 设计](../../architecture/v3.1/README.md)和[触发与回执](../../architecture/v3.1/运行时触发与回执.md)。

**多人版现行口径。** 登录后进入同一个个人助手入口，首页按账号读取个人消息与任务。超管另有全站任务入口，可查看任务、精简执行状态和成果，并按状态规则修改标题、暂停、取消、恢复、重跑和验收。个人对话、记忆、原始附件和任务输入保持本人范围。内部会话继续用于来源和绑定，产品入口按本人时间线组织。[单助手与多人运维实施方案](../../ClusBot-V3.1-单助手与多人运维实施方案.md) · [当前交付边界](../../ClusBot-V3.1-前后端一体设计评审.md#现行口径与交付边界)

**阅读顺序：** §0 先看一条使用路径和各入口；§1 看场景复审发现了什么；§2–4 看用户从哪里来、怎么把事办完；§5–7 看设置、后端契约和 A2UI；§8–9 看依赖与通过条件。F 编号对应业务能力，T 编号是独立验收组，BE 编号是后端交付项。

## 0. 打开后怎么用

**登录后直接进入按账号显示的个人助手。** 交代事情、查进度或问结果；点「查看任务」只看详情，点「在对话中引用」才改变输入目标。不必先到工作台建任务。模型理解、整理和提出候选，后端判定是否已受理、可执行以及实际发生了什么。

| 入口 | 看什么 / 做什么 |
| --- | --- |
| 个人助手 | 交代事项、追进度、看回执，上翻或查找本人的早期消息 |
| 任务清单 | 统一查看本人任务及其概览、运行、产物、回执。超级管理员在清单内切换可管理范围。 |
| 左侧待我处理 / 当前事项 | 待我处理只收决定和需人工接手的问题；当前任务只帮助定位在途工作。各处引用同一对象，待办不重复计数 |
| 右侧详情 / 窄屏单层详情 | 查看任务、决定、报告或证据；关闭回原来位置，打开详情不改变输入对象。无详情时保留助手时间线、原消息位置和输入草稿 |
| 查找 | 定位本人的早期消息、获准的任务和成果；结果直接回到相应消息或对象 |
| 账号与安全 | 侧栏底部头像显示真实账号和角色，打开「本人账号」。超级管理员另有「用户管理」。 |
| 设置 | 设置入口位于头像上方，按领域分组。MCP 和工具目录在实例内共用。 |

**实现与设计分层。** 旧单机客户端已有普通对话、部分任务引用和基准操作、单条隔离回复、部分设置页及会话 Skill/MCP 选择。多人账号、全站任务和助手工具已有后端接口。新版 SVG 定义卡片、表单、确认、回接及异常状态，客户端接入和跨对象回顾仍需验收。专用基准、发现和工单画面按本机模式联调。

## 1. 按场景复审：先消除前后冲突

不是把所有业务揉成一条演示。以下是复审中影响实现的缺口与唯一裁决；后续章节用同一口径。

| 复审发现 | 本版裁决 |
| --- | --- |
| “对话是入口”被理解为必须有可用模型，但冷启动、审批和故障救援不能依赖模型 | 首页仍是对话。无模型时不承诺自然语言应答，但固定设置、已有任务读取和已签发的明确动作仍可用 |
| “没有原会话也能接续”与“删除对话”之间缺归属规则 | 任务、决定、投递和会话独立。无可用原会话时进系统事项，用同一业务对象续办；无读取权时不显示对象内容，也不会借新会话绕权限 |
| 把所有跨会话信息和授权决定放在一列，会让后台噪音淹没真决定 | 待我处理只收有明确动作的决定和需要人工处置的异常。普通进度更新原卡；不可处理的异常明确责任方，不伪造按钮 |
| “预检通过才开跑”容易和预约已受理、等待资源混为一谈 | 区分不受理、已记录但待决定、已入队等待、满足派发条件。预约只锁定请求约束，不预占未确认的卡；到点重新检查 |
| “暂停”容易暗示正在跑的外部工作也停了；“超时”容易被误当失败 | 模型回复、任务控制、远端作业、资源占用分开呈现。未获远端确认前不报已停止；仍可能被原作业占用的资源不释放，模型或本地执行槽独立回收 |
| “从对话可以配置”容易变成把密钥贴给模型；“选了 MCP 就能调用”混淆作用域 | 对话可启动并回接配置，秘密只用固定安全输入。导入、探测、启用、绑定、授权、派发各有独立状态和回执 |
| “一轮选模型”没有说明是否会改变长期任务 | 先说明覆盖作用域。本轮覆盖不能静默改变会话默认或在途任务；冻结不允许绕过撤权或数据出域限制 |
| 已有场景编号不等于真的测过关键分支 | 每条验收写独立启动条件、可见和后台断言、禁止效果；语义相近但未执行对应边界的案例不计交叉覆盖 |

## 2. 产品壳、操作者与信息架构

### 2.1 默认打开什么，谁能操作

- **主导航始终包含个人助手和任务清单。** 顶栏查找可定位会话、任务、设置和账号。侧栏底部顺序为设置、折叠侧栏、账号与安全。 所有用户共用个人助手入口，打开时读取该账号自己的消息与任务。桌面主区由左栏选中项标识当前位置，直接显示进展或消息；无需另设一行同名标题。切换任务和设备不更换助手，同一时间线可跟进多项工作。当前任务只列在途事项（包括待审批、等回执），待我处理按独立决定计数；同一任务可出现在两处，读写同一对象，不重复审批。 不以专用工作台、资产库、成果库或工具页作为使用前置。对话显示结论、状态和下一步，详细业务对象按需展开。主要动作一眼可辨，不让所有内容都变成卡片。窄屏用单层详情，返回原消息和焦点。
- **同一个用户可以在不同场景承担不同职责。** 申请者可提交与读自己的工作，值守/审批者只在被授予的范围内处理决定，管理者可维护全局配置与可见性。名称只是用于说明，不是前端硬编码的权限角色；以服务端授权和返回的可用动作为准。无法确定负责人时交给有权限的管理范围，绝不广播资产详情。
- **界面可见不等于可操作。** 设置入口始终可达，但跨作用域数据、审批或有副作用的动作按后端权限。后台任务不要求窗口一直开；服务器离线时显示最后同步时间与暂不可确认的工作。
- **体验底线。** 靠留白、字号和表面层次，不用装饰线；图标与简洁文字结合（`Icon + 精简状态`），只读版本号与状态使用轻量无投影 Tag（等宽字体、`20px` 高），与可点击按钮明确区分，且 Tag 文本与同行单行标题统一使用 `line-height: 1` 配合 `align-items: center`，避免字体默认行距导致标签视觉偏上；**同一表格或列表中表达同一种枚举属性（如绑定来源、状态、指令触发方式等）的单元格须统一视觉形态**（全部使用语义化 Tag 胶囊或全部使用纯文本，不混用半行有框、半行裸字）；消息头发送者姓名与时间戳保持光学对齐与基线齐平（名用紧凑行高上提补偿，等宽时间戳按视觉基线微调）。文本/图标说明状态，不能只靠颜色；最小辅助字号不低于 `11px` 且满足可读对比度。常规卡片不堆叠重阴影，仅悬浮输入区（Composer）与浮出弹层/抽屉使用柔和外阴影；颜色与悬停过渡 `120ms ease-out`，面板/手风琴展开 `180ms`，并支持系统 `prefers-reduced-motion` 关闭位移。键盘可完成发送、对象选择、打开和关闭详情；动态更新不抢焦点。
- **macOS 窗口与侧栏。** 默认窗体 `1280 × 820`，最小窗体 `760 × 480`。展开侧栏 `220px`，收缩图标栏 `90px`；窄窗用抽屉。保留 AppKit 原生红黄绿，侧栏品牌从顶部安全区下方开始。品牌标志与应用名、描述的两行组合等高，使用与应用图标相同的图形。收缩后顶部主导航只显示个人助手和任务清单。展开与收缩的导航图标统一 `16px`，底部依次为设置、展开按钮、账号头像。「显示」菜单也可显隐侧栏。 [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) · [Apple Windows](https://developer.apple.com/design/human-interface-guidelines/windows) · [Apple App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons/)
- **标题和组选中状态。** 设置当前分类由顶栏路径和选中标签指示，内容从对应分组开始。分组标题 `14px`，控件文字保持可读。当前事项默认中性，鼠标悬停或键盘聚焦时才有对应反馈。账号区内使用真实子页导航，并向辅助技术标明当前页。 [Apple Settings](https://developer.apple.com/design/human-interface-guidelines/settings) · [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography)
- **当前事项按需呈现。** 存在进行中或待处理的事项时，展开侧栏显示当前事项列表，对话顶栏提供入口。没有待处理或进行中的事项时，列表、标题、分隔线和对应计数一并收起。任务清单作为独立导航保留。
- **任务清单。** 个人、旧本机及超管统一使用清单布局，范围和治理权限按账号判定。超管的范围行显示「全部成员」「仅看我的」「其他成员」及相应数量。服务端校验跨账号任务权限，按授权返回任务进度与产物，成员对话按所属账号隔离。没有任务时仍保留列表、筛选和空态。点击任务打开四标签详情抽屉。操作列依次展示改标题、运行与产物和任务当前可执行的状态操作。宽窗内三项同行排列，图标和文字居中对齐。完整工作从本人任务详情进入。
- **对话内卡片堆叠、层次与统一内容宽度。** 对话流中同一条回复若包含多个独立交互卡片（如确认卡 + 宿主可信凭据表单、跨账号暂停卡 + 报告验收卡），**默认垂直堆叠**并按自然内容宽度显示（`560px–600px`，不强行并排、也不撑满全宽导致高低错位与对齐失衡）；卡片内部严格遵守**「标题 → 说明/要点/表单 → 底部操作按钮」**自上而下阅读与决策顺序，严禁把按钮置于说明行上方。桌面端所有设置与管理页按布局规律统一分为两类：**高密度配置页统一采用两列 Master-Detail**（`05 模型`、`06 MCP 连接与工具`、`15 Skills 目录`，左侧目录 `320–340px`，右侧持久详情与编辑面板随主区撑开，不在左列与右侧面板间重复展开正文）；**表单与清单页采用统一 `1012px` 全宽布局**（`24px` 水平内边距）。仅在对话与任务浏览等不常驻全宽详情的场景，按需从右侧滑出 **`380px` 任务详情抽屉**。
- **当前事项点击与单超管防竞争机制。** 左侧栏任务区块统称为「**当前事项**」（收纳待确认决定与进行中任务），视觉上采用原生 macOS 侧栏轻量列表行（无边框透明底 + 柔和激活高亮，不堆砌白底小卡片）。点击「当前事项」条目主体时，**不伪造用户发言，也不伪造模型回复**，而是直接调用只读业务接口打开右侧 **380px 任务详情抽屉**（`概览 / 运行 / 产物 / 模型与 Token 回执`），模型离线时仍可用；点击「引用到输入」才把对象标签放入 Composer。**对于唯一超级管理员的对话与跨账号动态展示**：系统中仅有一位超级管理员，顶栏分段切换器采用清晰的双向文案 **`仅看我的 | 全站动态`**（不在按钮文案中添加易误解为禁用态的“(只读)”后缀）；为防止超管在个人对话中与原任务负责人并发修改引发版本（`revision`）竞争，且避免“聚合汇总”漏看单条任务变化，超管切换至 `全站动态` 时调用 `GET /api/v1/admin/task-notices` **逐条独立呈现每个成员任务动态**（默认收起全貌，仅显示**「来自谁 · 任务标题 · 当前状态 · 查看详情」**，不带并发写按钮）；具体跨账号治理操作由「**任务清单**」统一管理页（`GET /api/v1/admin/tasks?scope=all|mine|others`）在服务端 `revision` 校验下完成。
- **界面与 SVG 效果图纯净度要求（硬性约束）。** 界面与 SVG 效果图**只呈现最终产品中用户实际可见的内容**，严禁在界面或 SVG 中放置以下内容：
  1. **设计说明与实现备注**：如架构分工注释（“固定宿主控件”“A2UI 1.0”等内部协议标签）、规则解释框、未开放能力的说明角标或引导性设计注解；
  2. **开发期代码与字段标识**：如 Go 结构体名、JSON 字段名（`egress_fields`、`Work.ModelAttributes` 等）或原始程序枚举值（`true`、`null`、`not_checked` 等），一律转换为用户可读的自然中文状态；
  3. **为了解释设计而额外增加的 UI 组件**：不添加仅用于向评审者说明产品模式、操作方式或后端机制的徽标、提示条和占位控件。所有设计说明、接口映射与未实现边界统一沉淀在设计文档中，不进入界面与 SVG 画面；
  4. **配置修订号（`revision`）按分层静默展示**：禁止在界面中捏造不存在的“全局统一版本号”（如不存在的“全局 v18 / 在途冻结 v17”），也不在常规提供方列表、模型列表、角色卡或凭据表单中直接暴露令人误解的裸 `v12` / `v2` 标签；乐观锁 `revision` 由前端静默携带，仅在并发冲突（`ErrModelSettingsRevision`）时展示自然中文刷新提示，仅在模型展开详情底部元信息、任务运行模型回执及发生配置漂移追溯时使用明确中文标签 **`配置修订 #12`**，并配轻量 `ⓘ`（`info`）说明图标（不使用 `!` 告警图标），解释其用于防并发冲突与运行快照追溯；Skill 自身的语义版本（如 `v2.1`）继续正常展示。样稿中的继承关系与示例数据必须前后自洽（例如标记「继承默认」的角色，其生效模型必须与「全局默认」一致）。

### 2.2 消息、对象卡和详情怎么分

| 表达 | 使用条件 | 典型内容 |
| --- | --- | --- |
| 一句话或短答 | 只需理解，不需要保留动作状态 | 普通问答、来源解释、缺项、报告摘要 |
| 对象卡 | 需返回继续操作或活状态 | 任务、资产、等待、报告、连接、计划、跨来源待决定 |
| 详情侧栏 | 信息密度高，需要查证或编辑 | 步骤、日志、版本差异、证据、工具 schema、场景过滤 |
| 独立可信控件 | 明确授权、凭据或高影响动作 | 认证、扩权确认、外发、交付、清除数据、取消影响说明 |

## 3. 对话主链：按真实操作走

### 3.1 单条消息的完整生命周期

1. **发送、乐观上屏与流式回复**：输入文字、附件、引用消息、选择的对象和显式临时约束。客户端携带唯一 `client_message_id` 发起提交，**立即清空输入框并乐观渲染用户消息气泡**（对话流采用左右对称内边距，消息区与 Composer 左右边界严格对齐；持久化与乐观上屏的用户消息头统一右对齐展示当前账号显示名与圆形头像标识），气泡下方右对齐显示轻量状态（`发送中…` → 超过 400 ms 切换为 `正在理解意图…`）；服务端持久化后无缝替换为真实消息并隐藏状态行；断线或失败时在原气泡下内联提供 **`重试`**（复用原请求键防重复）、**`放回输入框`** 与 **`移除`**。助手响应统一使用无框 `message-assistant` 行实时流式渲染（经内存事件唤醒的 SSE `message.delta` / `reasoning.delta` 推送，支持可折叠 `思考过程` 与智能贴底滚动），不再单独套用白底边框卡片。
2. **理解与定位**：Router 可以拆成问答、只读查询、委托、计划、追问、修订、控制、配置和交付。对象类型和 ID 与正文分开提交。显式任务标签约束本次请求；引用是理解上下文，不得覆盖显式任务标签。没有标签时，唯一可信且可读的候选可用于查询；不可据此直接改任务。浏览侧栏不暗改输入对象。歧义才问一个具体问题；显示对象 ID、范围、状态和可区分依据。否定、条件问句、引用日志或工具描述不发起操作。多项意图分别回执，有依赖的等前项，互不相关的不互锁。
3. **计划和确认**：回显目标、时区/开始条件、资产/能力、计划版本或一次性步骤、不能自动核验的项。权限和动作影响均符合 §3.6 才直接受理，不反复要求批准；新增影响、目标不唯一或事实缺失时只呈现待决定部分。参数或资产变了，原确认不能继续用。拒绝一个分支不取消无依赖工作。
4. **运行和接续**：卡片绑定 Task、Step、Run、Operation、Wait 的具体身份。追问读事实，不重新执行。不用模型回答“是否已经停止”代替真实远端回执。修订只改未派发项，已派发项保留原版本，旧回执不跨代。任务终态不复活；重新跑明确创建后续或新执行代际。
5. **交付与后续**：说明已出结果、可核实覆盖、性能是否达标、资产是否验收四个不同结论，随后给证据和缺项。报告在原对话可更新、展开、下载；保存到本机、按权限下载/导出和向外部收件人发送是三件事；绝不从“帮我写报告”推导发送。用户可在此继续要求更换比较口径、修订下一版计划、与旧结果并列。

### 3.2 四条彼此独立的主路径

1. **普通交流 → 多意图 → 对象确认。** 问“SM 是什么，再查一下 POD7 是否空，先别跑”，直接给解释和只读事实，不建任务。遇同名 POD 时只暂停资产查询这一项，给对象 ID、位置和负责人供选择；独立解释照常给出。选中只作用于这条请求，侧栏切换不隐式改发言目标。
2. **零环境 → 安全接入 → 首次可验收委托。** 尚无模型：固定设置能手工配置和试答。之后从对话登记可信资产来源和 MCP，核对稳定身份、成员、拓扑、管理端点和责任；探测工具能否启动、查找、取证、取消，同步与异步能力分别标识。按需要选择已有方案、一次性计划或保存默认草稿；逐项回报自动可核验/需人工/未接通。只读工具并不发放基准写权限。认证或现场不可达时停在对应步骤，配置成功后回到原诉求。
3. **并行进行 → 追问 → 修订／暂停／取消。** 同会话有基准和另一项任务；修订未派发测项先给差异和受影响依赖。确认前版本若改变，提示重取并保留修改草稿；已发的 J17 仍用原约束取回。用户可停止回复而不改变两项任务；暂停只挡新的派发；远端取消未确认时继续显示运行和占用。后续进展更新原对象而非跳转到另一页。
4. **成果 → 取证 → 交付与再工作。** 跨两次基准结果看单项覆盖、缺失、实测配置、单位和来源。如果口径不同只并列，不生成伪增幅；可提供带缺项的阶段报告。下载由当前权限决定；外发独立说明收件人、内容版本及授权，不从“写报告”推断外发。允许续做缺项或新次任务，但不恢复旧终态或改写历史。

### 3.2.1 第一次接入：清单是引导，不是授权

| 需要补什么 | 这一步何时算核对 |
| --- | --- |
| 资产 | 能核对稳定 ID、成员和拓扑、端点、负责人、来源与时间；不把资产引用数算作实际 GPU 数 |
| 工具 | 登记、试连、schema/版本核对、允许调用各自独立；分别查能否提交、按原作业查状态、取证、取消；只读接通不等于写权限 |
| 测试模板 | 草稿写明必测项、依赖、参数、能力绑定、证据和阈值；经复核发布成有版本的模板。发布不等于下单、批准动作或自动设为默认 |
| 执行批准 | 单独核对主体、审批人、资产、动作、参数边界、日期/时区、并发、有效期与出域影响。批准后仍不保证已排队或一定派发 |

### 3.3 消息、附件与预览

- **消息操作**：悬停或键盘聚焦时显示「复制」「引用回复」「更多」；触屏可长按。复制默认只取正文，代码块有自己的复制按钮。引用支持整条或选中段落；Composer 显示可移除的来源摘要，发送后可从新消息返回原位置。引用不创建新会话，也不等于授权更改任务；一条引用若指向多个任务，不自动选中。删除或撤权时重查权限，显示来源不可用，不保留敏感正文缓存。
- **附件卡片**：发送前显示文件名、大小和上传状态，支持移除或重试。所选文件未就绪时不得静默漏发，可移除该文件后发送。文件卡在编写时位于输入文字上方，发送成功后仍在气泡正文上方。每条消息中的同一附件只显示一次，纯附件消息省略正文区。卡片可预览、下载、引用；任务产物还显示来源任务、测项与核验状态。关掉预览返回发起按钮和原阅读位置。
- **附件尺寸与图标**：气泡内用左对齐的紧凑卡，不拉满气泡。消息顶部的桌面附件与引用共用 216 × 40 px 外框；容器窄于单项时宽度适应容器；多个平铺、空间不足自然换行，长名省略但详情保留全名。先列 3 个，多余通过「查看全部 N 个附件」打开独立列表。卡主体打开预览（不支持则打开文件信息），下载单独操作；触屏操作应便于点击。16/20 px 线性图标按可信类型区分：表格网格、日志横线、压缩包拉链、栅格图片山形、PDF 折页、未知二进制代码符号，同时保留文字。类型未知不通过扩展名打开预览。
- **支持矩阵是产品目标，不是当前后端承诺**：可识别的纯文本、日志、代码、JSON/YAML 分段预览，CSV/TSV 按页表格预览；常见栅格图片可显示缩略图，PDF 用隔离的按页预览。Office、SVG/HTML、压缩包和其他二进制首版只给卡片与获准的下载，不内联或自动解包。未知文件、执行文件、安装包、固件、转储等显示已核实的类型、大小、SHA-256 和来源，不自动打开或执行；告知不能预览的原因。类型以服务端探测为准，文本与单元格作为文字渲染，不执行脚本、宏或公式。超限、扫描待完成或被拒时给明确原因，不用扩展名绕过。大小、页数和片段上限由服务端返回，前端不硬猜。
- **可看不等于能交给模型**：预览、下载、作为本轮材料和交给工具分别授权。用户显式引用后只取必要片段，标出实际页/行与截断范围。图片还需有效模型能力，原始二进制不给模型；经明确委托、授权且存在专用隔离分析器时，可以让工具产生可读摘要。资料授权失效时清理预览、撤掉旧操作，已下载到设备的文件不假称能收回。

### 3.4 Composer：写消息、选对象、看清会发生什么

| 层 | 常用内容 | 行为 |
| --- | --- | --- |
| 上方上下文 | 任务、引用消息/成员、待发送附件、斜杠指令胶囊 | 补全由光标处的触发符决定。`/` 显示以斜杠开头的可用指令，`@` 显示当前可见任务和成员。同一时刻只有一个面板，两种面板都在 Composer 正上方，左右边缘与 Composer 对齐（`GET /api/v1/assistant/composer-options`）。上下键选择，Tab 或 Enter 填充，Esc 关闭；打开模型策略时收起补全。OpenPencil 20 和 20A 分别呈现两种状态。每项标签支持一键移除 (`×`，未发送上传附件联动 `DELETE /api/v1/materials/{id}` 清理)；待发送及历史附件共用居中预览（`GET /api/v1/materials/{id}/preview`）。 |
| 中间输入 | 多行文本、粘贴或拖入材料（日志/CSV表格/Markdown/YAML/JSON/图片） | 默认 Enter 发送、Shift+Enter 换行。保留已选的 Ctrl/⌘+Enter 模式，发送按钮提示当前快捷键。中文输入法和补全候选先处理。输入区关闭引号的自动替换，指令格式失败时保留草稿；报错与等待提示统一进入对话流助手消息，不放在 Composer 内。 |
| 下方操作 | Unified 底栏：左侧保留 `+ 添加材料`（含轻量准备指示）；右侧为 `模型策略：按角色路由 ▾` 与发送按钮 | 所有会话画板复用同一 Composer 视觉壳；点击 `模型策略` 在该按钮正上方 `4px` 处右对齐弹出策略菜单（不压住左/中侧输入正文），明确区分**全局策略模式**（`按角色路由策略 [默认]` / `仅确定性查询 [零消耗]`）与**仅本轮回答临时指定模型**（带品牌 Logo），不与多阶段角色路由混淆 |

Composer 保持纯净，不承载告警、模型配置引导或发送报错；模型未添加、已有模型但未设全局默认/阶段策略、等待模型就绪、发送受阻等状态统一以 **ClusBot 助手消息** 呈现在对话流中（单屏绝不重复提示），并在用户完成设置后实时更新为「已配置 · 原提示已过时」。「设置 / 模型」页顶部提供「提供方与模型 | 阶段模型策略」正式平级切换入口。全站局部报错、版本冲突和状态回执均遵循[视觉规范草案 §5](视觉规范草案.md#5-信息反馈与报错展示规范)。

历史消息读取失败时，在历史区显示原因和「重试」，保留当前可读回复和输入区。用户消息气泡靠右、正文左对齐。浅色使用 `#E7F1FF`，深色将主题蓝混入面板底色并保持文字对比。对话流相邻消息块统一 `16 px` 间距（状态消息头到卡片保持 `8 px`），新消息或流式输出在用户处于底部（距底部 `≤ 48 px`）且无 `#message-N` 锚点定位时自动跟随滚动；用户发送消息立即回底。上滑浏览历史时暂停自动滚动，并在消息区底部居中、Composer 上方 `10 px` 处显示悬浮胶囊提示（有新消息/流式更新时显示主题色「↓ 新消息」或「↓ N 条新消息」，仅浏览历史无新动态时显示中性色「↓ 回到底部」），点击后平滑回底并恢复自动跟随；向上加载更早消息时保持当前阅读位置不跳动。

**消息气泡与 Composer 共用内容顺序和左基线。** 正文上方的任务目标、消息引用和各个附件卡共用一个可换行的横向容器。各项同宽同高，间距 8 px，同行上下沿对齐；下一项放不下才整项换行。正文或输入区在整组下方，和首项共用左边线。工具栏只保留添加、发送等操作。任务、消息引用与附件均用 216 × 40 px 外框、8 px 圆角、16 px 图标和同一行文字基线。任务名和 ID 表示目标，消息引用表示来源，文件卡在文件名右侧显示大小，发送前后沿用相同尺寸；发送前上下文可移除，文件可移除，发送后相同位置仅保留可读引用和下载，不能表现得像还能撤回内容。多个附件顺序不变、紧凑换行；空正文不留占位。Composer 只用一层表面，下方工具条不跟正文抢层级；用同一条消息的编写与发送对照图验收。

**T42 怎么选中**：点左栏任务或消息卡的「查看任务」只打开详情。点详情或任务卡的「在对话中引用」，才把「POD7 全套基准 · T42」放入 Composer，聚焦输入且保留已有草稿。也可从 Composer 的对象选择器明确选择。引用一条只关联一个且当前可读的任务消息，可把任务作为可见标签带入；不自动选择重名候选。若已有显式目标（例如 T42），引用来自 T43 的消息只追加其来源，不替换 T42。发送后该消息保留引用，Composer 默认清掉本轮标签；失败仍保留，结果不明按原键恢复。切换窗口、查看其他任务或关闭侧栏不覆盖未发送选择。任务标签不批准、不派发，也不改变默认方案。

### 3.5 修订详情：资产先行，操作只反映当前状态

**显示顺序**：涉及资产 → 本次变更 → 执行影响。首屏显示锁定的资产组和可核实节点/卡数（例如「POD7 · 40 张加速卡 · 节点数未核实」），标「范围不变」也照常展示，可展开实际目标和数据时点；范围有变化时逐项列新增、移除或范围缩小。将本次目标、当前占用和相对于基线的差异分开，不拿动态资产目录冒充任务快照。其下列「集合通信：移除未派发测项」「必测项：3 → 2」；不变的默认方案和保留的既有结果可简明说明。最后说明 DeepEP 是否继续、是否仍占用，依据实际回执。

**强调方式**：资产名与数量用高对比深色；紫色强调实际变更，琥珀色强调占用、待审批或待核实，红色只表示明确的阻断或风险，灰色表示不变。每项有文字与必要图标；颜色不替代状态。外层任务卡保留资产摘要。

**底部只放这个视图的主动作**。普通、可应用且已核验的预览用「应用修订」；关闭面板或返回任务不改计划，入口在标题栏或页签，不与提交并列成模糊的「暂不修改」。仅真有可丢弃的草稿才提供「放弃草稿」。无权或应由他人审批不能显示可点击的应用；有真实申请能力时按契约显示「提交审批」。过期或版本冲突显示原因并提供「重新预览」；无变化则不出现应用。提交中防重复，事件未知查原请求；成功显示新版本并把按钮替换为状态。暂停、取消执行只在任务控制内，不能混入修订底栏。高影响扩展独立说明对象、资产差异与影响，要求相应确认。

### 3.6 通用操作规则：什么时候直接办、问一句、预览或审批

**确认的是新增风险或未明确的选择，不是让用户把原指令说两遍。** 同一套规则用于任务、定时器、资产、报告、模型和工具配置；不根据某个页面是否已经有确认弹窗决定策略。先区分「用户要什么」「现在能改什么」「改了会带来什么」。

| 判定 | 产品行为 | 例子 |
| --- | --- | --- |
| 只查询，或只整理资料与草稿 | 直接给结果；不能因动词、引用或附件内容触发业务动作 | 「停了会怎样？」只解释；「整理成一份报告」生成草稿，不外发 |
| 明确目标、动作、范围，已授权，且操作的真实影响没有超出原指令，当前允许并具有受控恢复路径 | 直接执行并回执；可安全恢复则给对应操作，不额外弹「确定吗」 | 暂停某个定时计划的后续触发；给本次未派发步骤加「暂不派发」标记（若已具备能力）；更改一个不生效的报告草稿 |
| 目标、时间、范围或效果有两种实质不同的解释 | 只问最小缺项；保留已确定部分，无依赖的其它工作继续 | 「别跑第二项」却存在两组测项时，请选哪一组；如果无法判断「先别跑」是等待恢复还是本次跳过，不能自设恢复时点 |
| 动作已授权，但用户没有看过生成内容、接收对象、额外影响，或策略定义为高影响/必须先确认 | 给预览并要求批准具体后果；不问无信息量的「确认操作？」 | 发布新默认方案先展示覆盖范围；外发先对齐收件人、报告版本和数据范围；取消已派发作业先显示已发生效果与清理影响，并应用对应权限与策略 |
| 权限不足或需要独立审批人 | 明确缺失权限或审批人；仅在有授权的申请通道时提交审批。用户说「我确认」不替代权限 | 免除必测项、跨团队释放资源、关闭安全检查不能被「已确认」按钮绕过 |
| 无能力、事实未知、版本过期或远端效果待核对 | 不猜、不假报成功；只在安全可行时进行原操作对账。条件已变化则说明差异，重新评估而不是套用旧同意 | 已进入派发事务就不说「没发」；外发结果不明先查原请求，不重新发；预览期间条件变化则拒绝旧预览 |

**工作从哪一层改变，必须明确写出来**：

- **执行控制**只影响当前对象和执行范围，例如「暂停后续派发」「本次跳过本步骤」「请求取消远端作业」。基准任务级暂停和恢复使用本机派发链路。桌面账号模式可按授权查看已有任务和修订方案，并依据进度接口显示派发控制的可用状态。恢复时重新检查权限和条件。本次跳过只影响当前运行。暂停和取消都不能顺手改参数、默认配置、通过条件、原始证据或释放未知占用。
- **方案变更**修改步骤、参数、依赖或未来默认，必须分清「这一次」「之后的默认」「共享发布」。生成草稿、应用本次修订、发布默认版是不同动作。即使同一条自然语言提了两件事，也按各自权限与影响分开处理。
- **通过条件与例外**决定结果能否验收。「本次未执行」不等于「已通过」「免测」或「不再必测」。若仍缺必测项，报告保留原要求并标缺项；免测或替换证据必须有单独的政策、权限和原因，不能借编辑计划默默重算通过结果。
- **外部副作用**从申请到核实单独记状态，例如「取消已请求／远端已确认取消」「外发待送达／已送达」。本地回执只能证明本地受理或阻断；不可从它推断远端完成。

**谁判定和如何生效**：AI 只提出结构化候选（目标引用、动作、仅本次/未来、用户原文依据），不签发权限，不能把日志、引用、假设或建议冒充用户指令。固定控件可以直接提交同类候选。Go 按动作声明的允许范围、事务守卫、影响和审批策略判定，权限、对象版本、执行代际、当前状态、真实能力和幂等键均需校验。运行时在同一事务比较未派发/已派发并记录实际结果；若派发先赢，不自动升级为取消。需要确认时把提示绑定到动作、目标、版本、影响与有效期；重试核对原请求、审批以后仍按最新状态重验。回执写「已做、没做、待核对」，可逆动作提供有准确语义的下一步；不存在撤销能力就不显示「撤销」。

**研究依据**：[Google 会话确认](https://developers.google.com/assistant/conversation-design/confirmations)区分显式确认与在回执中回显理解；[Microsoft HAX](https://www.microsoft.com/en-us/haxtoolkit/guideline/scope-services-when-in-doubt/)建议不确定时缩小动作范围或澄清；[Apple HIG：Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts.md)不建议常见可撤销动作反复弹窗；[GitHub 环境审批](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/review-deployments)展示发起和按策略审批分离；[Kubernetes CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/#schedule-suspension)与[Temporal 取消](https://docs.temporal.io/develop/go/workflows/cancellation)分别展示暂停未来执行不能改已经启动的作业、发送取消请求与确认取消的不同。上面的运行时守卫是 ClusBot 自己的设计，不是把任何一个外部产品照搬进来。

**动作名称必须包含对象层级或实际效果**：例如「暂停后续调度」与「请求取消当前作业」，不要共用含糊的「暂停」。同为 Kubernetes，[暂停 CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/#schedule-suspension)保留已启动的 Job，而[暂停单个 Job](https://kubernetes.io/docs/concepts/workloads/controllers/job/#suspending-a-job)会删除活跃 Pod；这正说明不能从按钮动词推断真实影响。T17 要让停发与派发竞争：停发事务先提交时，真实派发调用为零、原必测项仍保留；派发已占先或效果未知时，保留原操作与可能占用并对账，不自动发取消，也不回执「已拦截」。验收用提供方替身核对调用次数与状态，而不是只检查文案。

**展示与回执**：执行控制已生效时，对话给实际回执并链接「执行记录」，详情显示作用范围、当前占用和不受影响的工作；不再同时出现「应用修订」。执行控制处于未知、仅受理或需要特定权限时只呈现事实与可用下一步。真正变更步骤定义、默认方案或通过条件时，才进入相应的预览或审批流程，两个视图不能共用成功按钮。

**首个确定性动作：本次跳过一个未派发步骤**。任务详情从服务端拿当前版本、稳定步骤 ID 和可用动作；只在本次目标清楚且允许时显示「本次跳过」。提交带当前方案修订号与请求标识；按钮即明确操作，不再弹「应用修订」。提交中只禁用该操作；服务器返回已生效才更新执行记录。状态或版本冲突时刷新、提示真实原因，不自动重试。网络未知先查原请求状态；同一请求重放必须保持原请求标识。对话发起同动作时，只有目标与动作被明确识别、Go 已通过同一准入并返回实际结果，才可以说「本次已跳过」。缺少能力时不显示成功，也不把普通续聊转成方案删除。

**当前落地边界**：明确的「本次跳过」与专用会话指令已接入独立执行控制，不使用删除测项替代。选中任务并在专用入口自由描述时，模型只生成待确认建议，界面显示实际动作和测项，再由 Go 重验确认；普通聊天不附带执行意图。方案修订仍走「预演→应用」。独立暂缓/继续、验收例外、全量附件在线预览和现场作业未因样稿而上线。

## 4. 非对话工作和业务完整性

### 4.1 系统事件如何变成人可以接手的事项

后端先分类并去重：**定时到期**依配置产生一次有限任务；**可信回执**匹配原任务/代际或留待对账，不新建任务；**外部观测**先记录事实，只有满足已发布规则和授权才可能触发工作；**需要人工决定**才登记待办。自主继续不等于发了通知，更不等于同意。来源是系统就标系统，不伪造用户话语。

| 来源情况 | 用户从哪里接手 | 状态如何变化 |
| --- | --- | --- |
| 本人助手里已有原消息 | 更新该用户可见的任务卡；轮到本人处理才进入待我处理 | 已读/稍后不解除等待；决定生效后更新同一对象 |
| 系统触发或旧来源已不可读 | 从获准的系统事项接手，显示责任方、时效与证据入口 | 按当前权限显示任务事实，旧私人来源的正文保持不可见 |
| 无权读或决定已失效 | 不返回详情；有权看状态时只给受限提示与下一步 | 不缓存敏感正文；过期、撤权、他人已处理都重取权威状态 |

通知与待办分开：待投递、已投递、失败只按渠道回执；未读、稍后、解决是用户处置。重复事件归并但不吞独立对象；静默时段只影响通知，不取消原任务或审批截止时间。批准、拒绝、待补材料由固定控制向同一后端确认，模型离线时也能完成。没有现行授权的外部接触或敏感发送不自动发生。无模型时只能处理已知对象和已签发的明确动作，不把自由输入重新分类，也不授予新权限。

### 4.1.1 可选回顾：自上次查看有变化

这是**默认折叠、可关闭、只读**的变化入口；如有权威计数，放在主区上方的进展入口，展开后按「已办完 / 仍在跟进 / 需要你」给简短事实和证据回链。不是每日简报、通知或助手发出的历史消息，不注入对话流，也不抢焦点。实际决定仍去同一待办，对象和计数不得重复。侧栏仍以按需对象详情为主，不能默认变成另一份待办工作台。

「自上次查看」需要同一主体、工作范围和有效权限下的持久查看基线；与拉取游标、事件时间、登录时间分开。只有显式查看才推进该范围的查看基线，后台同步、跨设备收包或打开 App 都不自动视为看过。水位只前进到实际显示给这一主体的事件，查看变化不关闭或批准待办。游标过期、无基线、范围变化或撤权时取当前可见快照，改称「当前状态」，不猜覆盖了多少离线时间。无模型用固定事实模板。不改变免打扰或不订阅日常跟踪的选择。

**现状：** 已有单会话事件与主体待办事件，不等于跨对象回顾或共享查看基线。该界面标为目标设计；权威来源和读基线未接时，不默认出现。

## 5. 全局设置、会话绑定与故障救援

**模型提供方配置可用连接，模型档案声明能力，策略决定使用，权限决定可做什么。Skill/MCP 能装进全局，但必须区分启用、会话选择、任务冻结和操作授权。**

| 区域 | 必须能做的事 | 生效规则 |
| --- | --- | --- |
| 提供方和凭据 | 多连接、协议/地址、本地/远端、认证、超时、停用、轮换、接通检查 | 拆测试连接、认证、列模型和最小实际应答；列不出仍可手填。只支持已实现的协议；系统注入显示出处不回显密钥。验证与开为默认是两件事 |
| 模型档案 | 模型 ID/别名、上下文和输出预算、图片/文件、结构化/工具、推理档和实际限制 | 区分提供方声明、探测、手工覆盖、未知。未知不假设支持，只有支持才传推理参数。保存前显示生效值和影响 |
| 角色策略 | 普通对话、Router/计划、执行解释、报告可继承全局或分别配置；预算、并发、回退、数据范围 | 新请求：硬权限/预算/数据边界先校验；本次、会话、业务、角色及全局的覆盖顺序见 §5.2。在途工作读冻结版本。撤权优先于冻结。不同提供方、额外成本或数据出域不无声回退 |
| Skill 目录 | 导入来源及指纹、校验资源、版本、启停；查看摘要并按需展开正文、引用；创建/复核经验提案 | 导入≠执行脚本，启用≠调用权限，绑定≠发布计划。可选择本轮/以后此会话/此任务；任务锁定引用，禁用后不新读或执行 |
| MCP 目录 | 登记、认证、握手、工具/资源与 schema 探测、变更、停用和审计；连接凭据与本机进程启动分别审批 | 已连接≠有权调用；绑定范围包括连接、工具、用途、目标与时效。步骤的能力映射另有版本。变更默认不改已执行，漂移需回审；只读取证和取消可有独立权限 |
| 外观、环境、数据 | 语言、时区、主题、快捷键、无障碍、通知偏好；工作区/网络和本机执行限制；保留、导出、清理、审计 | 提示影响、来源、是否需重启；必须可在无模型时进入。配置冲突保留草稿，支持回滚到有效版本；诊断分别显示实际模型、时延、可知用量、缺口，不泄露秘密或内部推理 |

配置工作链：在对话内创建草稿→必要时通过可信安全表单输入凭据→验证/预览→保存/启用→返回原对话明确“仅本轮”“以后此会话”或“给此任务”，再重新核验权限。解绑只改作用域，不卸载共享连接、不取消在途操作。没有可用模型时，用设置里的固定入口完成同一配置链。

### 对话工具与页面分工

个人助手的对话区承接查询卡、操作预览、确认和执行回执。ClusBot 内置工具复用自身的任务、模型和设置接口。外部系统接入继续使用 MCP。设置与详情保留完整编辑和无模型时的入口。

- **资产发现归属。** 资产候选、发现来源与定时计划的预览和确认在个人助手对话中展示（画板 11）。发现来源不可用时，对话保留同名状态卡。数据与诊断查看工作区和存储。提供方连接诊断从模型页进入。搜索「资产发现」回到对话入口。
- 查看模型时分三层呈现：全局默认和角色配置、当前任务或会话的 Skill/MCP 绑定、指定执行的模型请求和供应方回执。未报告实际模型时，保留“请求模型”的文案。
- 查询任务、成果、待处理、计划和记忆显示结构化结果。超管跨账号安排附带所有者 ID 和任务 ID，确认卡显示所属账号、操作和参数。后端重新检查权限、版本和当前状态。
- 连接密钥、密码、出域授权等从对话转入可信表单，按权限打开对应配置。用户完成、取消或返回后，保留原会话与草稿。
- 确认失效或版本冲突时，提供重新读取再预览的入口。已受理的异步任务用当前任务状态显示，回执本身只表示这次调用已返回。

当前自然语言工具入口为显式工具调用，普通消息中只有少量已登记的问法可由支持卡片的客户端选择直达工具。确认绑定会话，五分钟内可提交一次或取消；重启和过期要求重新预览。卡片目前不自动入普通对话历史。后端入口及会话接入约定见 [对话工具 API](../../ClusBot-V3.1-联调前待确认项.md)。

### 5.1 配置的状态、覆盖和救援顺序

每项都要能看见草稿、验证通过或失败、已生效、被覆盖、已停用/失效。账户级、工作范围、角色默认和本轮设置均显示实际生效来源。保存失败先保留原配置；输入未提交可保留草稿，但秘密从不进入通用草稿。试连不默认启用。切换默认会影响后续模型选择；已发出的请求继续使用已选模型，恢复执行仍需核对绑定和检查点。编辑时若发现服务端版已变，展示差异请复核而不是静默覆盖。恢复旧版后再次检查权限、能力与数据范围，不能借回滚恢复已撤销凭据。

### 5.2 一个助手，按阶段组合，不是一个模型通吃

默认模型是最后一层继承，不是所有工作的指定模型。只接一个可用模型能启动；缺少某阶段必需能力时，该阶段显示缺项，不假装全功能可用。常规请求每阶段只用一个模型，不把每条消息群发给多个提供方。

| 环节 | 谁决定用哪个模型 | 例：POD7 完整基准 |
| --- | --- | --- |
| Router · 理解用户要什么 | 确定性入口能处理则不调模型；开放表达走适合短上下文、结构化输出、低延迟的受理角色 | 把“全套基准”读成结构化请求；Go 核对选中的集群和用户授权 |
| 普通对话 | 回复角色，允许配置本次回复覆盖；文本和视觉候选按照真实输入能力过滤 | 解释“SM=60 是什么意思”；上传图片才考虑允许接收图片的候选 |
| Worker · 制定或修订方案 | 规划角色；已发布方案可直接复用。约束不明、步骤依赖复杂时才选更强的推理模型 | 对照 Skill 和历史，提出修订草案；不运行测试、不把建议写成正式清单 |
| Worker · 排查与执行解释 | 排查角色；按需使用长上下文、工具调用或图像能力，只给当前授权的数据切片 | 解释日志异常；固定步骤派发不因排查模型切换，模型只能提出候选动作 |
| Worker · 汇总与报告 | 报告角色；可单独用长上下文模型，但仅送授权后的证据；数值计算与口径校验由结构化数据和代码完成 | 把已核实数字和遗漏写成报告，不把缺结果算作通过 |
| 定时、调度、权限、派发、等待、对账、验收事实 | **Go，不选模型** | 定时唤醒、匹配作业回执、校验资产与必测产物；没有模型也能继续对账 |

**当前接通范围。** 后端已有提供方目录、共享连接和凭据、独立档案、稳定默认引用，以及普通回复、通用 Router、任务 Worker 和三类基准专用角色绑定。通用角色仍受同协议、地址和凭据边界约束。按业务覆盖、有序候补、带历史的通用单轮覆盖和规划／排查／报告独立分阶段策略属于目标；生效预览不能据此宣称支持切换。单机的「单独问一个模型」仅发送主动确认的本条文字，档案或凭据变化时停止发送；多人版暂未开放该执行入口。

**目标路由规则**：由 Go 先确定阶段、任务类别和最低能力（如图片或结构化输出），再按主体权限、数据出域、上下文上限、预算与可用性过滤。对新工作，在允许覆盖的角色中按「本次显式覆盖 → 会话绑定 → 该业务在该阶段的覆盖 → 该角色默认 → 全局默认」取首个已设置层；该层不合格不静默跌到下一层，除非配置了同样满足防线的候补。业务覆盖只写类型与角色，不由模型临时创建规则。固定任务的后续调用读取已记录策略版本；撤权、凭据失效和当下数据范围仍优先。更换策略不重派已提交操作；模型调用失败不等于远端操作失败。

目标候补链独立配置；仅在允许的故障类型如网络、超时或限流发生时使用，并受最大重试、并发和预算限制。认证失败、能力缺失、禁止出域、未获授权都不借回退绕过。跨提供方须预先允许，不能导致新数据出域或成本越限；无合法候选给可处理的错误。投递已发出的工具调用不属于模型候补。策略预览显示计划请求的模型或别名及选择原因；普通 Runner 的执行详情已能分别显示请求模型和提供方返回的模型标识；这个历史展示不等于所有角色都可以切换。两者可以不同，提供方未返回就显示「未报告」，不能用请求别名冒充实测。回执另记角色、策略版本、回退原因、耗时和可知用量，不回显密钥、原始日志或内部推理。

业界对照：[OpenAI Agents SDK 按 Agent 绑定模型](https://openai.github.io/openai-agents-python/models/)、[LiteLLM 候选能力过滤](https://docs.litellm.ai/docs/router/learn/selection)和[回退策略](https://docs.litellm.ai/docs/router/learn/reliability)，以及 [OpenTelemetry 对请求模型和响应模型的区分](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)。ClusBot 只采纳角色分工和候选约束，不引入统一全局强制覆盖，也不照搬自动跨提供方回退。

新增或编辑模型时，可以从服务返回的清单中选择模型 ID，也可以手填。选择条目后，表单以模型名称或模型 ID 标识当前编辑对象。基础字段包括模型 ID、上下文窗口（tokens）、推理能力和图片输入能力。服务明确声明的推理强度、图片、工具调用、结构化输出及文件能力可预填。服务未提供的字段显示未知，允许手工补充。显示字段来自服务声明或手工设置，试答回执展示实际的文本试答结果。实际执行继续按绑定版本和有效权限核对。

连接和模型表单在所选条目下方就地展开。桌面并排字段的标签和控件分别对齐，窄屏按相同顺序排为一列。保存和取消采用相同高度，在表单底部与输入区右边线对齐。一次只编辑一项，保存或取消后收起表单并回到触发操作的那一行，保留当前分类和滚动位置。保存失败时保留表单，并在发生字段错误时标明出错字段。提供方的连通、认证、列模型和试答结果分别显示，连接故障在对应提供方处给出原因和修复操作。凭据只通过受信表单写入，密钥不进对话或通用草稿。

没有模型时仍可打开设置，聊天的「打开模型设置」直达模型页。首次配置从「添加服务提供方」开始，填写连接信息、保存并试答模型，再选为全局默认或普通对话的阶段模型。会话页从实际生效的普通对话路由读取可用状态。回到会话时重新检查。保存和试答各有回执，实际启用取决于当前路由。聊天也能发起相同的配置草稿、预览或绑定，必要时开同一可信表单。安装、启用、绑定和授权各按其作用域生效。多人版显示全局已启用能力与本次任务的生效绑定；个人助手首页不设会话配置入口。

**单机旧版已落地的配置入口**：设置含 Skill 目录、文字草稿、正文复核、版本与指纹、启用/停用；也可按 [Agent Skills 主文件格式](https://agentskills.io/specification) 预验并将单个 `SKILL.md` 导入为未启用草稿。范围或原始文件变化要重新预览，不改变原启用版本，不授予工具权限。完整目录/压缩包、脚本、引用及附属资源不在此入口。工具与连接可从设置直达既有管理功能。在对话标题展开「本会话配置」，可选择或解除已批准的 Skill 版本和可用且已授权的 MCP 只读工具。选中不代表调用，也不授予权限，不要求模型。会话忙或已归档不能修改。两个编辑窗口共用同一服务端代际，保存和解除都核对版本；冲突保留草稿，不自动重发，已开始的运行继续使用原快照。

目标 Composer 右下角固定为「**模型策略：按角色路由 ▾**」选择器（与设置页“直接选某一个模型”区分）：点击后在该按钮正上方右对齐弹出策略菜单（对应 `composer-options` 返回的 `reply_strategies`），默认项「按角色路由策略（自动匹配各阶段）」，并提供「仅确定性查询（不调模型）」及分割线下方的「仅本轮回答临时指定模型」列表。正常仅有一个候选或无模型时相应降级显示。单轮覆盖只改这条消息的回复角色，Router、计划、排查和后台报告保持各自策略；自动启动的任务、审批和只读固定查询不因该策略改为其他后台模型。已显式选择文字模型但材料需要视觉时，提示换到允许视觉的模型或去掉视觉材料，不暗换；固定查询回执可显示「未调用模型」。

## 6. 前后端契约：界面只表达事实

### 6.1 状态与动作的对应关系

| 同时发生的事实 | 对话用语 | 可做与不可做 |
| --- | --- | --- |
| 请求已发送、受理未知 | 提交待确认，查询原请求 | 允许查状态、按原键恢复；不能写已入队 |
| Task 已受理、尚未派发、资源不够或资料陈旧 | 已受理；等待具体资源/现场复核 | 可看依赖、调整未派发部分；不能显示远端执行中 |
| 等待时间/人工/依赖 | 等到时间、等指定决定、等依赖 | 真正满足的纯时间等待可重评；人工与外部超时不自动通过 |
| 已派发且响应丢失或迟到 | 远端效果未核实、下次核对时点 | 先查原作业。除非确认未执行，或提供方明确保证同键重交无重复效果且运行时复核许可，否则不重交；前端不自行发新键 |
| 任务暂停，远端仍跑，模型已释放 | 已停止新派发；作业仍在运行，资源仍占用 | 可查并按授权处理远端；“停止回复”只管本轮生成 |
| 已申请取消，夹有迟到有效结果 | 正在核对是否已停，显示实际影响 | 原作业仍可能占用时不释相关资源，不报作业已停；结果仍可入账但不得复活任务 |
| 已取得结果但缺证据或阈值 | 指标收到/部分已核实；未证明达标 | 可查缺口、验证原件；不强行转绿 |
| 权限、版本或动作到期 | 状态或权限已变化 | 旧卡只读或裁剪，拉最新再决定；不重放旧确认 |
| 模型离线但运行时可读 | 生成不可用；可查任务和设置 | 固定读取、决定和有权限的控制仍可用 |

**统一状态用语，不拼成一枚总状态：**

| 分量 | 用户用语和边界 |
| --- | --- |
| 受理 | 提交待确认 / 已受理 / 未受理；受理不表示远端运行 |
| 任务控制 | 等待办理 / 办理中 / 已阻止新派发 / 已结束；只有对应接口支持才出现暂停或继续 |
| 步骤与等待 | 等前项 / 未派发 / 本次跳过 / 等决定 / 下次核对 …；无可信核对时点不倒数 |
| 远端作业 | 已提交 / 运行中 / 效果待核实 / 已请求停止 / 远端确认已停止；没有远端作业就别造状态 |
| 资源占用 | 仍占用 / 已释放 / 待核对；数量须明确可信计量单位，未知不填 40 卡，也不拿资产目标数替代 |
| 证据 | 已收到 / 已核实 / 缺原件 / 配置不符 / 未评估；可信分母才显示 x/y，跳过的必测仍在分母 |

任务控制、远端作业、占用和证据是四层独立事实，只显示适用的分量。结论也分别说**执行是否结束、必需证据是否齐备、性能是否达标、资产是否验收**，普通任务不用硬塞四格。不同口径只并列，别算增幅；不适用或未评估不能归作通过。状态不只靠颜色。

### 6.2 通用目标契约与当前接口

当前路由和请求字段按[联调契约](../../ClusBot-V3.1-联调前待确认项.md)实现。以下是跨对象能力的目标要求，发布版以实际可用字段和动作权限决定交互。

- **对象快照**：类型、稳定 ID、版本、状态分量（Task/Step/Run/Operation/Wait/租约/证据与审批分别给）、采集时间、来源引用、机器原因码与可读原因、允许动作和禁用理由。详情按权限分页，秘密永不进入响应。前端用事实编排表达，不另造业务状态机。
- **动作**：使用服务器计算的动作引用，绑定 actor、目标、当前版本/执行代际、约束及期限；带请求键和允许的输入。区别返回已受理/已应用/已拒绝/待核对。「禁用」只是展示，后端重验；相同键相同内容只应用一次，内容不同报冲突。后端无能力时明确返回，不给假按钮或悄悄授权。
- **消息与业务事件**：消息带稳定消息 ID、会话、原始来源和对象引用；持久业务事件带游标与对象版本，和模型临时文本流分开。重连从游标恢复，过期拿快照；去重并拒绝倒退状态，历史回放没有副作用。对象越权时客观提示当前不可见，不把受限内容留在旧缓存。
- **消息材料和影响范围**：请求分别携带引用消息/片段、任务对象、附件/证据 ID 及会话模型覆盖，不从正文猜授权。预览需返回资产快照和当前占用、差异与适用动作；材料接口区分上传状态、预览/下载/用于模型的授权、类型与大小上限、服务端可读预览模式。
- **待办/通知**：查当前主体可见的待办快照、查询来源、标读、处理后显式更新以及重复归并；状态与 Pending Decision、实际通知投递和审批审计分别记，不能把已登记当已提醒。
- **前端可靠性**：草稿、待发送请求键与选中对象可恢复；阅读位置以稳定消息加局部偏移保存。翻旧消息只显示新消息提示；切 App、缩放、开/关详情、重连不跳顶。旧网络响应不得覆盖新对象；窄屏全屏详情关掉回原消息和触发焦点。日志和大表惰性加载。

### 6.3 复合状态不覆盖彼此：示例与裁决

以下是具备运行证据时的人读示例，不是新的状态枚举，也不代表画出来的动作已接通：

> POD7 基准 · 未继续派发。DeepEP 作业仍在运行，关联资源仍占用，实际数量待核实。下次核对 21:30（等待记录）。
>
> 可以查看作业和证据。当前基准的任务级请求停止不等于单独取消一个远端作业；本机模式可对尚未派发的测项分别暂缓或继续；已派发测项仍按原作业核对。没有获准且已接的动作不出按钮，不直接重跑。模型不可用不影响这些事实。

- 接口结果明确哪层更新：同一次事件可改变 Operation，但未必改变 Task、验收或租约。派发应答未到，历史卡只显示最新可信时点；“超时待核实”和“远端确认终态”分别取证。
- 真正改动的动作都返回目标版本、一致的接受/拒绝原因和查状态的引用。确认过期、版本冲突、权限撤回和缺能力分别提示；只在有相同受理键时可重试提交，普通网络重试不等于可重复业务动作。
- 审批、待办、报告都按后端授权读取；隐藏字段不能靠 React 事后遮住。撤权更新到已打开的侧栏、历史缓存和 A2UI（重新裁剪或清空）。解释中展示材料来源、缺项和截断范围，绝不展示内部思维或凭据。
- 活动中的本地草稿、不可确认请求、详情与历史锚点分别保存。浏览旧消息时只提示新消息；用户发送/明确点击跳到最新才移动。窗口失焦、切 App、重连后恢复的是当前视图，不会逮住旧请求把另一对象覆盖掉。

### 7.1 Go 输出与 React 消费

1. 助手工具先按已有权限执行查询或生成操作预览。Go 从获准业务结果构造 `surface`，其内容是同一个 `surfaceId` 的 `createSurface` 与 `updateComponents`。目录 ID 固定为 `https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json`。查询、预览及回执继续保留原有业务字段和 HTTP 状态。
2. React 在对话区校验协议、目录和组件树，按白名单渲染 `Column`、`Row`、`Text` 及有限的卡片组件。文本为普通文本。未知组件、超限、无效引用或循环使用固定提示降级。首批可用交互是白名单 `toggle_details`，纯本地展开当前卡片。
3. 客户端不从 A2UI 内容读取 URL、运行代码、发业务写请求或取确认 ID。A2UI 不携带凭据和确认 ID，不启用整个数据模型回传、远程函数或双向函数调用。敏感操作继续通过固定接口重复校验。
4. 普通对话在明确请求设置预览或限定范围的运维建议时可以返回工具卡。02 由 Go 在本地目录按用户点名唯一匹配角色、模型及提供方，宿主按最新配置打开确认卡和空凭据表单。歧义时由用户选择，预填阶段不写入。03 的修订请求绑定可确认的任务和当前方案修订号，模型解释修改要求，Go 校验可改测项、差异和执行影响，用户另行应用；版本冲突保留草稿。
5. 17、18 先查询授权范围内的本地健康数据。只有相关对象同时具备模型外发授权，才向任务 Worker 模型发送最小范围的健康汇总，模型填写标题、说明和选项。未获外发授权时仍展示本地数据和原因。任务进度、POD 归属、可用动作和模型用量来自各自的核验接口。Go 为建议及选项分配标识，按认证会话记录选择；执行需要对应业务入口另外核对目标、权限及能力。
6. 20 的基准规划用默认模型解读用户要求和已获准的本轮上下文，展示模型撰写的待核对建议。方案版本、引用任务及其历史冻结目标读取本地数据；核对类别、结果状态和执行入口由应用定义。
7. 21 的提案风险边界、执行结果、工单和根因依据各自的业务记录显示。未确认根因时显示调查进度。Token 图表保留提供方用量回执中的数据缺口。

### 7.2 两端验收

- Go 测试覆盖标准 `1.0` 消息、同一 surface 引用、字段裁剪、无确认凭据进入 surface，以及原业务权限和确认重放保护。
- Web 验收查询卡、详情展开、有效确认、取消、冲突、异常渲染降级和普通消息草稿。macOS 封装使用同一 Web 客户端，另做 WebKit 运行验收。新版多人界面的登录、切账号与表单回接随页面接入做端到端验收。

## 9. 独立验收组与交叉覆盖

每组自己的初始状态，至少一个负向/恢复分支。断言不仅看某个提示，还应核对记录、次数、资源占用和未发生的效果；模拟与真实现场分别记，不用走通一条总流程替代其他能力。

### 9.2 哪些必须拆开跑

**T13 增补（分开记录，不互相抵算）：**

| 操作 | 通过条件 |
| --- | --- |
| 跨视口和失焦：引用 T42 写未发草稿，查看 T43；切 App、窄屏关闭详情并分别用 Esc、关闭和「回到输入框」 | 返回原消息锚点、局部偏移和触发控件；显式「回到输入框」才聚焦原稿。迟到 T43 不覆盖 T42。不跳顶；320 像素、200% 缩放和长中文下按钮不遮正文 |
| 重连：回放旧事件、接迟到回执；另测游标过期 | 同一任务/代际归并，保留最新权威状态；游标过期注明只读到当前状态。不重复派发、不复活终态、不把收到时间当实际执行时间 |
| 模型离线：从任务或待办手动查当前状态 | 固定控件仍可读取已有授权的任务与证据，需模型的解释单独标不可用。手动刷新不是重新发送、取消或审批 |
| 打开附件/报告后离线，另一端撤回读权再重连 | 去掉旧正文、旧链接和旧动作；读不到原位置则回附近可读消息并说明。不从本地缓存泄露被撤权内容 |
| 主体 A 有查看基线，主体 B 或其他范围没有；手动展开可选回顾 | 仅有效基线内显示变化；缺基线只显示当前状态。手动查看才更新，不发每日通知、不插入助手历史 |

- **普通问答、零接入、已有条件的下单**是三个不同起点。只读接入成功不得作为写动作通过的证据。远端执行没有可追踪身份或原件时，明确不可自动验收。
- **审批、外部回执、定时计划**各有独立到期和恢复用例。用基准预约不能代替周期计划的编辑、停用、漏跑；拿到本地回执不能代替外部效果证据。
- **偏好和 Skill**分别验：偏好的本轮/持久、来源撤回和派生失效，不能以 Skill 提案通过替代。**验收、报告生成、下载、外发**分别验，不拿完成一个动作推定其余权限。
- **真实中文输入法单独验收（T15 子例）**：在打包的 macOS App 和支持的浏览器中，显式选中 T42，使用系统中文输入法输入「把本次尚未派发的单机带宽改为 90 秒」。用回车确认候选词，不得发送请求，草稿与 T42 保留；候选面板中的 Esc 不得清除 T42 或关闭应用详情。再明确点「发送」，服务器只收到一条关联 T42 的消息；返回方案预演，不写入修订，另点「应用修订」才提交。用开发中实际支持的宿主记录行为，不能只靠合成键盘事件或 `isComposing` 推定通过：[WebKit 的组合事件顺序报告](https://bugs.webkit.org/show_bug.cgi?id=324380)说明部分宿主中候选确认的回车可能出现在 `compositionend` 之后，该报告不是 ClusBot 已复现的证据。
- **客户端和后端都要验**：Go 查越权、状态迁移与持久结果；前端查键盘、动态焦点、断线重连、降级显示；至少一种大列表和长历史。仅检查文案或静态样式不能确认业务闭环。
