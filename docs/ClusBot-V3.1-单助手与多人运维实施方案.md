# ClusBot V3.1 多账号简化设计

所有账号共用同一个 ClusBot 和「个人助手」页面。消息、任务和个人资料按不可变账号 ID 归属。既有内部会话可继续承载运行和追溯，产品和 API 无需独立助手 ID。本文和新版 SVG 定义目标行为。

**当前边界：** 服务器模式提供按账号登录的工作台，本机模式继续使用本机口令。各环境提供的领域动作取决于配置、账号权限与已安装的执行器。

## 安装、登录与账号管理

- **页面初始化。** 安装人员直接在页面填写用户名、密码及确认密码。部署阶段由部署者通过部署环境限制初始化入口的可达范围，创建首位超管后再开放日常访问。应用不发放安装码。初始化状态随数据库持久化，创建首位超管与关闭初始化在同一事务完成，并发提交只有一次成功。
- **角色。** 超级管理员创建、编辑、停用及恢复账号，维护头像、姓名和角色。普通用户查看本人资料并修改本人密码。最后一位可用超管不能停用或降级。超管另有全站任务管理权限，可查看任务信息、执行状态和成果，并执行任务控制和验收。个人对话、记忆及附件仍由本人访问。
- **密码。** 本人改密校验当前密码。忘记密码联系超管，超管为该账号设置临时密码，撤销旧登录；用户以临时密码登录后先设新密码，再进入助手。公开页面只提供登录和首次初始化。服务端保留密码哈希、登录限速和可撤销会话，日志和审计不含密码。
- **接口。** 沿用初始化状态、登录、本人改密及超管用户管理接口，调整建号和重置为密码流程。首位超管创建请求只需用户名和密码，页面做确认密码校验。本人资料来自登录状态，不依赖额外助手 ID。

停用账号已撤销其登录会话；当前实现未按账号停用状态统一停止后台任务或定时工作，重启时也会按已有账号目录恢复运行器。页面只能据此说明登录失效，不能承诺任务已暂停、远端作业已取消或资源已释放。停用后是否禁止新派发、如何处理在途作业须先明确并另行验证。

## 按账号拥有的任务与消息

1. Go 从验证过的登录会话取得主体。发送和委托受理时，将主体和请求键写入持久记录。异步分类、重试、定时派发和真实任务创建继承该主体；任务、计划与来源保持可追溯。客户端提交的所有者字段不能改变归属。
2. 消息流、任务、报告、记忆和文件存入该账号的业务库及工作区。查询、分页、详情、下载、引用、实时订阅、模型取材和执行控制都使用这份存储。运行记录和工具结果回到产生它们的账号，不同账号的同名任务和请求键互不干扰。页面草稿随客户端账号状态隔离。
3. 登录后从同一个「个人助手」入口读取本人的连续消息、当前进展和待处理项。打开任务详情后返回原阅读位置和草稿。账号切换时清除上个账号的页面数据与订阅，重新读取当前账号的数据。
4. MCP 和 Skill 由超管在实例级维护。业务库读取同一份配置，MCP 调用重新核对授权和版本，结果只写入所属账号。直接调用和任务调用的历史均按账号隔离。Skill 的个人经验和证据不进入共享目录。

## 实施顺序与验收

| 环节 | 实施与验收 |
| --- | --- |
| 首次安装与账号 | 替换安装码接口、启动提示、激活与恢复码流程；校验并发初始化、重启、超管建号与重置、本人改密、停用撤销会话 |
| 任务与历史 | 在现有收件、路由、建任务和定时链路贯通账号所有权。旧单人数据只在部署方确认归属后迁入。用 A/B 两个账号覆盖详情链接、搜索计数、下载、操作、实时流及模型上下文 |
| 前端 | 评审初始化、登录、个人中心、超管用户管理及任务图后，再实现页面并联调；保留附件排版和已有任务事实表达 |
| 清理 | 不接入上一版组、派单、交接及独立助手身份接口。若旧构建已创建相应表，先确认数据和迁移安排，再决定清理时机 |

## 后端接口与部署

- `GET /api/v1/bootstrap` 查询初始化状态，`POST /api/v1/bootstrap` 提交用户名和密码。服务器模式继续监听本机地址，通过配置的 HTTPS Origin 提供服务。首位超管初始化前，由部署环境限制入口仅安装人员可访问。
- `GET /api/v1/session` 返回当前账号及 `must_change_password`。超管创建账号时提交 `password`，忘密时向 `POST /api/v1/admin/users/{id}/password` 提交临时密码。临时密码登录后，通过 `POST /api/v1/me/password` 提交当前密码和新密码，随后重新登录。
- 实例库保存账号和共享配置。`account-data/<账号ID>/` 下分别保存业务库、上传文件和工作区。账号首次请求个人业务时创建存储，服务启动时恢复已有账号的待处理工作。旧单人库的业务数据须由部署方确认所属账号后另行迁移。
- 离线 `backup` 和 `restore` 一并处理实例库、个人库、附件和工作区。恢复后需要重新登录，MCP 连接重新验证后才可启用，既有排队任务须人工确认后再运行。若实例根目录仍有未归属的旧单人数据，备份操作会明确报告，避免漏备或把它分给某个账号。
- 服务器模式开放个人消息、任务、计划、附件、记忆、成果及共享 MCP 和 Skill，以及按账号隔离的资产台账和验收查询。基准派发、工单与资产借还继续使用本机运行链。
- 服务器模式由登录会话确定账号，普通用户的个人业务数据限本人，实例共享能力按授权可见；全局模型设置、用户管理和全站任务由超管操作。普通用户可读取脱敏的当前模型路由和本人执行回执，不能据此取得模型目录或全局设置权限。必须修改临时密码时，除登录状态、退出及改密等账号入口外，业务接口不可用。
- 服务器模式的超级管理员可在配置发现来源后创建计划、查看观测和纳管候选。未配置来源或普通账号访问状态时返回 `source_unavailable`。

### 助手对话

内置助手工具调用现有业务接口。服务器按发起人的登录身份和运行模式筛选目录，复核查询及写入权限。Go 将查询摘要和操作提示输出为受控 A2UI 1.0.0 消息。本机 Web 已接入，macOS 封装共用该客户端。写入的目标、参数、确认与取消通过固定组件解释和提交，账号与凭据走可信表单。多人工作台沿用同一助手接口和卡片契约。详见[前端组件分工](ui/personal-assistant/前端设计.md#7-a2ui-100对话内的渲染与交互)。


### 超管全站任务

`GET /api/v1/admin/tasks` 跨账号列出任务，返回 `owner_id` 和分页游标，可按既有任务筛选参数查询。用 `/api/v1/admin/tasks/{owner}/{id}` 读取详情，其下 `/runs`、`/artifacts`、`/artifacts/{artifact}/content` 分别读取执行状态、成果列表和成果文件。该入口也支持 `PATCH /{owner}/{id}` 编辑标题，以及在任务路径下用 `POST /pause`、`/cancel`、`/resume`、`/acceptance` 暂停、取消、恢复或重跑、验收。写入沿用任务版本和状态规则，任务及后续执行继续归原账号。任务目标、范围和交付要求由原账号维护，跨账号恢复或重跑沿用原任务输入。个人接口仍按登录账号访问。

## 状态与执行边界

任务状态、单次运行、远端作业、资源占用和证据分别读取。接口返回受理或助手工具返回 `completed`，只表示该次调用已返回，不能据此认定远端完成或成果已验收。暂停阻止后续领取和派发，已派发作业仍须核对；派发与暂停竞争时，以服务端回执和实际派发记录为准。远端效果未知时先核对原操作，在可确认终态前保留可能的占用，不凭超时重发或显示已释放。外部派发、回调与占用回收应通过本机运行链验收。

模型路由现有全局默认及已接通角色绑定，绑定失效时不静默切换。普通 Router、对话回复和任务执行角色的显式档案受同一有效端点、协议和凭据约束；设置界面中的按业务覆盖和有序候补仍是目标。设置截图中的常规偏好、可在线保存的执行限制、完整数据保留和诊断导出也不能当作现有 API。具体接口、权限与联调验收见[联调前待确认项](ClusBot-V3.1-联调前待确认项.md)。
